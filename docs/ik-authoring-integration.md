# IK authoring integration and production hardening

Milestone v0.6.6.4.3 integrates the existing visual rig IK authoring tools with Animation Editor and hardens import and preview ownership. Package SemVer remains `0.7.5`; authored formats remain version 1.

The [artist guide](artist-workflow.md#creating-ik-on-a-new-character) contains tutorials for new and existing characters, dependency warnings, save/reload and the four target/bake ownership domains.

## Editor synchronization and safety

The header editor tabs retain one shared scene and document pair. `RigEditor.refresh()` rebuilds preview consumers when IK definitions change, and `AnimationEditorState.updatePreviewRig()` invalidates rig-bound selection, timeline discovery, inspector sampling and animation preview without installing animation snapshots. New constraints appear immediately. Source `CharacterDefinition` data remains immutable. Rig Tweak mounts `RigIKPanel` with the existing `AttachmentController`; target defaults, settings and gestures use rig history, while target/mix keys use animation history. Modes retain independent dirty states.

Both IK inspector areas use native disclosures, and collapsible inspector sections start closed. Disclosure changes retain mounted controls and drafts without entering authored history. Inspector section spacing and rig-selection guidance have additional vertical padding. The shared rig hierarchy controller clears selection when the selected bone is clicked again, retaining focus and leaving history and dirty states unchanged.

The wider browser pass exposed an animation ownership bug during recovered-clip navigation: selecting the already active clip could reinstall its saved/inactive snapshot. `AnimationEditorDocument.selectAnimation()` now retains the active working snapshot unless explicitly discarding. A real recovery/controller regression checks two new clips, reselection and independent Undo/Redo.

Constraint names are stable IDs. Rename patches reject explicitly and list affected documents; no reference migration is implemented. Live dependency checks cover all working clips, including inactive/new clips, empty IK track placeholders, baked `disabledIKConstraints` metadata and registered specialized host references. Deletion, chain/endpoint changes, undo/redo, reset and recovery cannot invalidate these references. Animation restoration validates against the current rig as before. No command cascades or remaps keys.

Compatible raw rig JSON imports now accept IK additions and settings changes rather than requiring the original source IK array. Hierarchy, artwork identities, skins, asset and full schema checks remain. Removal, identity and chain/endpoint changes still pass through `assertIKConstraintChangesAllowed`. `RigEditorState.assertCanRestoreDraft()` exposes dependency failures for import feedback while boolean recovery preflights remain available. Failed preflight leaves authored data and history intact.

## Runtime and export

The existing priority-ordered two-bone solver remains authoritative. Static puppet-local targets supply missing animation coordinates; animated X/Y and mix channels retain existing weighted evaluation. Explicit world targets own position, late-bound providers own position and influence, and explicit mix overrides retain influence ownership. Clearing overrides returns control to animation/defaults. Facing remains an outer puppet transform. Baked clips retain clip-local suppression to avoid double-solving.

`TwoBoneIKConstraint.targetProvider` is a read-only accessor for the current callback. Preview reconstruction retains external targets, providers, enabled state and explicit influence overrides on retained constraints. Rig controls leave those target owners intact; Animation Editor fixed-preview toggles replace only their own callbacks. Editor-owned fixed providers use the current scene puppet when projecting their pinned local coordinates. Callback references are released on shutdown/failure and never serialized.

Rig JSON preserves exact IK data and settings. Package capture combines the current rig with every working animation and existing skins/artwork. CharacterLoader validates constraint IDs before runtime playback. Gizmos, drafts, selection, history, ownership and callbacks remain outside JSON. Targetless legacy rigs and existing version-1 characters retain compatibility.
