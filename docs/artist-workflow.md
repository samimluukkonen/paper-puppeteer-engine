# Artist workflow and production character packages

[All guides](../README.md#guides)

Starting without character files? Follow [Creating Your First Character](creating-your-first-character.md) to build a rig, import your own sprites, make the first animation and export a portable character.

For the integrated pose → graph → variation → cleanup → recovery → scene workflow, follow [Advanced animation workflow](advanced-animation-workflow.md). It includes the actual controls, separate history owners and common troubleshooting.

The shared character workspace keeps rig, artwork, skins and animation documents together. Both editor views offer **Character package** above the command bar. This combines current authored data with applied artwork into a downloadable ZIP, validates the result, and provides an isolated production runtime preview.

The [standalone developer guide](runtime-integration.md) takes the exported character into another Phaser application without editor code.

## Starting a project and building scenes

Start at **Project Workspace** (`/project/`) and choose **New Project**. Add a new character or register an existing character ZIP/example, then open its Rig or Animation Editor. Follow the rig, artwork and animation steps below. **Feature Guide** opens the existing task guides in the appropriate editor.

Choose **+ New Scene**, open Scene Editor, add the character as an Actor, then schedule movement and animation actions. Preview, scrub and refine timing. **Download scene package** exports a portable runtime scene ZIP. **Export Project** saves the complete editable project ZIP; reopen it with **Import Project**. A project ZIP includes a project manifest and shared artwork mapping; use a scene package for standalone runtime playback.

See [Project Workspace](project-workspace.md), [Making Your First Scene](making-your-first-scene.md), [local autosave](local-autosave.md) and the [v1.0.5 verification report](personal-production-readiness.md).

## Preparing artwork

Export separate transparent body parts as static PNG or WebP. Keep padding deliberate, use descriptive filenames, and plan each pivot around the joint where that piece rotates. Consistent image dimensions simplify replacement; different dimensions are supported through explicit pivot policies. Limits are 10 MiB, 8192 pixels per side and 16 megapixels per image; a character may contain at most 50 MiB and 64 megapixels of images.

Keep `character.json`, the rig, skins, animations, optional poses and images in one character folder. Paths are relative to `character.json`. Nested folders are supported. Use plain paths without absolute URLs, parent traversal, backslashes, percent escapes, queries, fragments or ambiguous trailing dots/spaces. Paths must also be distinct ignoring case for portable extraction. Texture keys identify image resources; bone, slot, attachment and skin identifiers identify authored objects. Keep these identifiers stable when changing filenames.

Choose **+ New Character** in the header to start from scratch, including before a character loads. Enter a name and a unique ID; the suggested ID remains editable. Creation opens an independent unsaved draft in the Rig Editor with one root bone, an empty default skin, no artwork and no animations. It does not copy an example character. See [new character workspaces](new-character-workspaces.md) for initialization, validation and lifecycle details.

Use **Hierarchy → Build skeleton** to name the root, add child bones and create slots. Use **Artwork import & replacement → Import new artwork** to add PNG/WebP files to the artwork library, then create attachments using those assets and assign them in the default skin. An imported image does not automatically create bones, slots or assignments. The entire [rig-building workflow](rig-building.md) works through the editor without writing JSON. The editors do not write repository files.

## Rig and attachment authoring

Use [Rig Editor](rig-editor.md) to select joints and adjust their placement relative to parents. Moving a joint changes the hierarchy's bind geometry. **Artwork Offset Editing** and **Sprite Origin Editing** align artwork independently of joint placement; **Slot Transform Editing** aligns attachment mounts. Inspect bone parentage in the hierarchy. Numeric fields and canvas drags use rig Undo/Redo. See [artwork alignment](visual-artwork-alignment.md) for exact pixel pivots and offsets.

In [slots, attachments and skins](visual-attachment-skins.md), create attachment entries from available textures, assign them to slots, and create or edit skins. Slots name stable mounts on bones; attachments name stable artwork entries. Skin overrides can inherit, select an attachment or explicitly clear a slot. Standalone manifest skins keep their runtime precedence over embedded rig skins. Package export includes both embedded skins and current standalone skin files.

**Download rig.json** exports a JSON checkpoint. Editor tabs already share the same live rig, so no file transfer is needed between them. Save that download and place it at the manifest's rig path yourself. Standalone skin downloads require the same manual placement. A rig download does not include replacement images.

## Creating IK on a new character

1. Choose **+ New Character**. In **Build skeleton**, select the root and add a child, then add that child's child. Place the joints so both chain segments have a nonzero length. Bone IDs can describe any shape, such as `base → segment → tip`.
2. In **IK constraints**, choose **+ Add IK Constraint**. Enter a unique, stable constraint name and select the three directly connected bones. Leave **Initialize target at current end effector** checked to start at the tip, or enter a target explicitly, then choose **Create IK Constraint**.
3. Drag the target crosshair or edit **Target X/Y**. These are puppet-local rig defaults, before facing, camera and scene placement. Enable **Live solver preview**, adjust **Bend direction** and **Influence**, and compare using rig Undo/Redo. Unreachable targets keep the requested coordinates while the solver clamps the limb.
4. Download the rig and use **Reload exported rig** to verify it. Use the header's **Animation Editor** tab to retain this same working character. Choose **+ New Animation**, select the new IK target in the timeline, and set X/Y with **Set Target Key**. Move the playhead and set another target. Set **Influence (mix)** keys separately when needed.
5. Scrub and play to check the motion, then export animation JSON or **Download character ZIP**. The ZIP includes the current rig and all working animations, including new clips. **Reload exported package** runs it through CharacterLoader and the regular runtime. No example IK or JSON edits are needed.

## Editing IK on an existing character

1. Open the character in Rig Editor and select a constraint in **IK constraints**. Inspect its chain, target, bend, influence, priority, enabled flag and endpoint offset. Existing names remain stable IDs.
2. Adjust the target and supported settings. **Enabled** disables/enables solving without deleting animation keys. Rig edits use rig Undo/Redo. In Animation Editor, **Editor Mode → Rig Tweak** offers this same IK panel at the paused animation pose; switch back to Animation mode to edit keys using animation Undo/Redo.
3. Read dependency messages before changing a chain or deleting a constraint. They list every working animation with an IK track, including inactive clips, baked suppression metadata, and registered host references. Referenced deletion, chain and endpoint changes are blocked. Renaming is unsupported because names identify animation references; no keys are silently removed or remapped. Static target, influence, bend, priority and enabled edits preserve those references.
4. Download and reload the edited rig, or import a compatible rig JSON. Imports retain the skeleton/artwork compatibility checks and reject unsafe IK reference changes. A rejected operation retains the working documents and histories. Original-source reload is also blocked if it would remove a newly referenced constraint; keep or restore that constraint first.
5. Return to Animation mode, select each affected clip, scrub and verify its motion. Animated target coordinates may hide changes to the static default. Export the full character ZIP and verify it in the runtime preview.

| IK data                 | Owner and behavior                                                                                                                                                                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Static rig target       | Rig JSON default, shared by all clips. Missing animated coordinates fall back to it. Rig edits create no animation keys.                                                                                                                     |
| Animated IK target      | Clip-local X/Y and mix keys referring to the stable constraint ID. Animation history owns these edits.                                                                                                                                       |
| Runtime target override | Host world target or late-bound provider, such as foot planting or weapon grips. Explicit targets own position; providers also own influence. Releasing the override returns control to animation/defaults. Runtime state is never exported. |
| Baked IK bone keyframes | Ordinary bone rotation keys plus clip-local `disabledIKConstraints` metadata. The metadata suppresses solving for the baked clip so the motion is not solved twice.                                                                          |

See [IK integration and verification](ik-authoring-integration.md) for implementation boundaries and regression coverage.

## Animation authoring and sprite replacement

Open the Animation Editor for the character. Choose a clip, select a bone/property, place the playhead and commit keys. Timeline navigation, interpolation, playback mode/FPS, events and key operations are documented in [animation authoring](animation-editor.md). [IK authoring](ik-animation-authoring.md) supplies target/mix keys; [IK baking](ik-bake-commit.md) converts authored IK to ordinary bone rotations with clip-local suppression. [Onion skinning](onion-skin-controls.md) previews neighboring runtime poses. [Mirroring](mirrored-keyframe-authoring.md) operates on authored pose/key data.

To start without animation files, choose **+ New Animation**, enter a unique name/ID, duration, FPS and loop preference, then Create Animation. The empty clip previews the rig's bind pose and supports the same bone/IK keys, events, playback and Undo/Redo. Multiple new clips remain in the workspace when switching selection. **New / Unsaved** persists until an individual JSON export checkpoint. Complete character ZIP export includes every new clip and registers its file in the exported manifest automatically.

To replace a forearm, choose its artwork asset and explicitly select shared or individual scope. Import the image, compare dimensions, select normalized/pixel/manual alignment, Preview, then Apply. See [sprite replacement](sprite-replacement.md). Preserve the attachment ID so every skin and slot continues to refer to the same logical piece. With a differently sized image, inspect the pivot and adjust artwork origins/offsets as needed. Existing animation keys are unchanged.

Switch to [Rig Tweak](animation-rig-tweak.md) at a paused animation pose to correct the elbow joint. Rig history and animation history stay separate. Return to Animation mode and scrub or play the existing keys. Artwork history is a third, independent session history. Download a complete package from this editor to combine the rig tweak, current clip, other session clips, skins and replacement binaries.

Use the header's **Rig Editor** and **Animation Editor** tabs to change views without reloading the character. Both routes share one scene, rig working copy, artwork controller and skin catalog. Each clip retains its pending keys, saved baseline and Undo/Redo history when you choose another animation; its playhead and key selection return with it. The animation package includes pending edits in inactive clips too. Rig Tweak reuses the same rig history at the paused animation pose; the full Rig Editor starts from the bind pose. Committed edits survive both transitions. Uncommitted animation previews offer a discard/cancel choice before a mode change.

Opening an editor in a separate browser tab or typing its URL starts a separate session. Complete local drafts retain committed rigs, skins, all working animations and applied artwork bytes in IndexedDB. Wait for **Local draft saved** before refreshing, then use **Recover Draft** to open a detached project working copy. Recovered work remains unexported; Undo/Redo histories restart. Older JSON-only drafts remain a fallback. Export a character or project ZIP for a disk copy before leaving the workspace. ZIP import opens a runtime verification preview and retains all authored documents. Rig JSON import in the shared workspace accepts the existing hierarchy and bone artwork identities, with validated IK edits subject to live dependency checks; an incompatible rig is rejected with the current session intact. Open another character to work on a different skeleton.

## Exporting and verifying a package

1. Finish focused numeric fields and gestures. Apply or cancel every artwork proposal; proposals are never silently exported.
2. Expand **Character package** and choose **Download character ZIP**. Export captures committed authored data and applied artwork once, before asynchronous asset reads. It includes the manifest, rig, embedded/standalone skins, animations, optional poses and every manifest image, including inactive attachment artwork. Attachments remain in the rig as required by the existing format.
3. Resolve reported issues and retry. Metadata uses existing runtime validation: missing rigs/skins/clips, duplicate IDs/names, unknown bones/attachments/textures, unsupported versions and invalid JSON fail. Package checks reject unsafe/colliding paths, missing/invalid image headers and atlas/frame references other than the static whole-image `__BASE` frame. Export failure leaves working data and checkpoints intact.
4. Save the ZIP in your chosen location. Browsers can initiate a download but cannot confirm that you retained it on disk. No repository file was overwritten.
5. Choose **Reload exported package** to decode the exact exported ZIP snapshot into an isolated runtime preview. Choose animation, skin and facing. This uses the existing `CharacterLoader`, texture-loading pipeline and `Puppet` playback, including authored IK and baked animation data. Preview errors are shown inside the dialog; close it to return to your unchanged editor session.
6. Reopen a saved editor ZIP using **Import ZIP for runtime preview**. This validates it before opening the preview. Invalid/interrupted imports retain the existing authored editor session. The importer accepts the UTF-8 stored ZIP subset emitted by this editor; re-compressed, encrypted, ZIP64 and general third-party archives are unsupported. Standard ZIP tools can extract exported archives.
7. Extract the ZIP into a character directory in your application's public/served assets, then load its `character.json`. This file placement and any source-control commit are manual. Paths inside the ZIP start at `character.json`; the downloaded filename supplies the character name.

Existing relative metadata/image paths are retained when possible. A shared replacement keeps its texture key and image path when the extension matches and no other texture key uses that path. Replacing an aliased source image or switching PNG/WebP generates a distinct matching image path. Individual overrides get distinct deterministic texture keys/image paths while bone/attachment/slot/skin identities remain unchanged. Generated clip, skin and image filenames receive numeric suffixes when they collide after sanitization or case folding. Conflicts between existing manifest paths still block export. Pixel-preserving pivots serialize into ordinary normalized origins; pivots outside 0..1 use an equivalent artwork offset, including attachment rotation/scale, to preserve rendering without extending the format.

Use this public API inside your own Phaser scene; see the [runtime integration guide](runtime-integration.md) for installation and lifecycle details:

```ts
const url = new URL('character/character.json', document.baseURI).href;
const definition = await loadSceneCharacter(this, url, { allowWebp: true });
if (!definition) return; // Shutdown while fetching metadata or decoding images.
const puppet = new Puppet(this, { definition, x: 380, y: 380 });
```

It imports `loadSceneCharacter` and `Puppet` from `paper-puppeteer-engine/runtime`, then calls `puppet.play('idle')`. See the [developer guide](runtime-integration.md) for the full verified excerpts, event/skin controls and resource cleanup.

Use `allowWebp: true` when the package contains static WebP. PNG and WebP dimensions are checked before decoding; animated WebP and other formats remain rejected. Runtime texture-key uniqueness across characters remains the host application's responsibility. Scene hosts should follow the cancelable loading pattern in the development guide for shutdown/error handling. Runtime facing is a host option; the package retains authored transforms and animation/mirroring results, not editor-only facing, camera, onion, mirror or IK preview settings. Add preview-only IK chains to the authored rig if production clips need them.

## Checkpoints and losing a session

The package panel reports **Rig**, **Animations**, **Assets** and **Skins** independently. Initial clean values mean “matches loaded source.” A successful ZIP download initiation records a package checkpoint for exactly the captured authored data and blobs. Edits made during the download stay modified. Undoing back to that checkpoint becomes clean; a failed download does not establish one. A file-only rig/skin/animation download never establishes a complete-package checkpoint. Individual JSON checkpoints retain their existing navigation behavior; the package status can still show Modified after all edited JSON files have been individually exported.

Package checkpoints do not change per-document Undo/Redo, source definitions or the original artwork. Individual editor dirty labels continue to use their own saved/exported baselines. Consequently an editor can still warn on navigation after downloading a package: edits since the last completed local save and session histories would be lost, and download completion cannot prove source files were updated. Save the ZIP before accepting that warning.

Character changes, navigation out of the workspace, browser refresh and closing use the browser's existing unsaved-session protection where supported. Pending image decode/proposals and animation previews are protected too. Editor-tab navigation and browser Back/Forward between editor routes retain the live owner and require no discard of committed documents. Rig import/reload checks pending artwork before canceling proposals; compatible rig reloads retain applied artwork. Complete local drafts recover committed authored data and binary artwork; Undo/Redo histories remain session-only. Changes since the last completed local save can be lost. If the newest revision is corrupt, select the previous revision in **Recovery drafts**. Storage failures retain prior snapshots and show instructions to export and retry. ZIP preview/import does not discard authoring, so it needs no discard confirmation.

## Troubleshooting

| Symptom                                                 | What to check                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Joint moves but artwork seems misplaced                 | Rig Editor edits the skeleton and alignment. Select the correct joint, sprite-origin, artwork-offset or slot mode; inspect the attachment used by the active skin.                                                                                                                        |
| Replacement shifts when dimensions change               | Compare old/new dimensions and choose normalized, pixel-preserving or manual pivot alignment before Apply. Use artwork Undo/Revert for image changes and rig Undo for alignment changes.                                                                                                  |
| Animation disappears after a view change                | Animation Editor creates motion; select the intended clip. Header editor tabs retain clips and their histories; a separate browser tab starts another session.                                                                                                                            |
| Structural correction should not create keys            | Pause at the problem pose and use Rig Tweak. Return to Animation mode to verify motion; rig and animation Undo/Redo are separate.                                                                                                                                                         |
| IK bake is disabled                                     | Select an authored two-bone constraint, use valid sampling FPS and turn off fixed runtime IK preview overrides. Read the bake error/fidelity report; increase sampling when between-key drift is excessive.                                                                               |
| Skin shows the wrong piece                              | Inspect slot assignment, attachment identity and sparse skin overrides. An explicit cleared assignment hides a piece; removing an override inherits the base assignment. Runtime hosts reset to the default then `applySkin` to match the editor; `setSkin` alone empties unlisted slots. |
| Export reports a path, reference or image error         | Resolve the named manifest resource or attachment; use static PNG/WebP and whole-image frames. Apply/cancel pending artwork proposals, then retry. Failed exports retain the session.                                                                                                     |
| Runtime cannot find the exported images                 | Extract all ZIP entries, serve the directory over HTTP and load its `character.json`. Preserve relative paths and use `allowWebp: true` for static WebP. Check host texture-key conflicts.                                                                                                |
| ZIP preview works but edits are absent after refreshing | Character ZIP import opens a runtime verification preview; **Project Workspace → Import Project** opens an editable project. **Recovery drafts** restores completed local snapshots, including actual artwork bytes.                                                                      |
| Large timeline responds slowly                          | Filter tracks and expand only relevant properties; reduce onion ghost counts while authoring. See measured limits in the release-readiness report.                                                                                                                                        |

## Architecture and verification

`CharacterDefinition.manifest` retains an immutable original manifest alongside `rigFile`, standalone skins and animation paths. `ArtworkController.exportReplacements()` exposes applied immutable blobs and logical scopes without temporary Phaser keys/URLs. `AnimationEditorDocument.packageAnimations()` supplies the active authored clip and other committed session clips without changing selection/history.

`buildCharacterPackage()` snapshots inputs, assembles detached version-1 JSON and images, and runs `CharacterLoader` over an isolated in-memory file map. ZIP encoding is dependency-free and uses stored entries because PNG/WebP are already compressed. Editor downloads and ZIP imports run encoding, decoding and table-based CRC32 checks in a dedicated module worker. The worker transfers completed buffers back to the editor; caller inputs retain their ownership. A 60-second deadline bounds package operations, and session replacement or teardown terminates pending workers so late results cannot install checkpoints or previews. Bounded file counts/sizes, path checks and strict local/central directory agreement guard import. Preview object URLs are generated only after package validation, belong to a disposable runtime lease, and never enter exported metadata. Each runtime package preview owns a separate Phaser game; shutdown releases puppets and texture loading before URL revocation. Controller teardown cancels pending requests and releases subscriptions. Existing rig handles, IK gizmos and ghost/overlay lifetimes are retained.

The [production verification report](production-asset-verification.md) records changed APIs, regression scope and exact command results. Automated coverage is in `tests/characterPackage.test.ts`, the existing sprite/rig/animation/runtime suites and local `tests/browser/characterPackage.spec.ts`. It covers full-file/binary round trips, source immutability, shared/individual replacement precedence, normalized/pixel origins, paths, bad JSON/versions/IDs/images/ZIPs, snapshot races, checkpoints, cancellation, URL disposal, unchanged poses and runtime playback with IK/baked data and both facings. Local browser scenarios exercise artwork import, elbow correction, ZIP download/import, animation/skin/facing playback and repeated preview teardown in both editors against development and production builds. Browser checks remain local-only.

For a representative human manual workflow, follow the preparation, rig, animation and export sections in order: import transparent parts; assign slots; adjust the existing hierarchy/joints; align origins/offsets; export/place the rig; open Animation Editor; author bone and IK keys; enable onion skinning; replace/align a forearm; tweak the elbow; return to Animation mode and verify earlier keys; download the package; reload/import it; play its clips through the runtime preview; extract it and load it in the host application. Include Undo/Redo, all skins, facing, crossfades/layers in the host, and repeated character/editor changes. This is a documented manual checklist, not a claim that a human manual pass was performed.

Scene authoring and runtime choreography are available through the [Scene Editor](scene-editor.md) and [Actor/choreography APIs](choreography-production.md). Physics, ragdolls, mesh deformation, automatic artwork generation/rigging, advanced retargeting and a general image editor remain deferred.
