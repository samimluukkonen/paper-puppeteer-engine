## Implemented hardening and API status

Added ten complete character ZIP → validation/CharacterLoader → export cycles that compare every path and byte, including replacement image binaries. A failed-load regression verifies an existing live character still emits events and the next valid load succeeds. Ten repeated load/play/skin/facing/teardown cycles with one and twenty simultaneous Puppets alternate explicit destruction and scene shutdown, asserting all captured mock containers/images are destroyed, scene update/shutdown listeners return to zero and disposed players stop delivery.

Added one continuous local browser artist workflow using supported controls: configure the shipped rig, import/align artwork, create a skin/assignment, create a clip, author and mirror keys, enable onion skins, author moving IK targets, add an event, bake selected IK, replace artwork from the other view, correct a joint with Rig Tweak, download the ZIP and play it with a new skin in an isolated runtime preview. Downloaded metadata and image bytes are inspected. Artifacts remain in ignored test output.

Updated a stale browser assertion that predated shared per-clip sessions: dirty clip switching retains its authored keys/history; fresh clips start clean and unfinished transform drafts do not transfer. Version checks now reject drift between package, lockfile, standalone tarball and changelog. `check:release` combines the existing checks sequentially. Package/example versions and installation snippets move to `0.6.5`.

Resolved a sparse-skin handoff defect: ZIP preview and the standalone sample used complete `setSkin` replacement for editor-authored sparse overrides, hiding unlisted body parts. Both now reset the default then `applySkin` the selection, preserving explicit clears and avoiding accumulated overrides. The continuous browser workflow detects this through visible limb motion after skin switching.

Resolved a macOS Control-click selection defect: the following native context-menu event could reselect a toggled-off marker and discard the rest of the group. The marker and workspace menu controllers now respect event ownership. Control-modified context menus preserve the pointer handler's selection; ordinary right-click still selects an unselected marker. The browser scenario also dispatches this event explicitly so the regression is covered on other platforms. Scrolled drag assertions now compare numeric times with subpixel tolerance, and interpolation sampling uses exact time input instead of hundreds of redundant keyboard operations.

Corrected compact-desktop overflow: the preview's 240 px minimum plus timeline/header/package chrome made the 1000×768 page 24 px too tall. A 180 px preview minimum lets the grid fit that viewport while retaining the timeline minimum. Browser harness corrections also open the bone hierarchy before selecting hidden controls and assert that inactive shared-workspace onion controls are hidden rather than removed.

Fixed missing full-Rig-Editor numeric autosaves: inspector edits deliberately suppress scene notifications to keep focused fields intact, but the full-rig status callback refreshed only package checkpoints. It now refreshes the shared rig recovery owner too, so its existing debounce, validation, snapshot and history semantics apply to numeric edits, source replacement and reload recovery.

Rig canvas tests now calibrate the fitted camera using rendered head/torso joint references from both shipped characters, rather than legacy hard-coded screen coordinates. Compatible reload checks verify retained preferences/history; incompatible topology imports are rejected atomically and the hierarchy rebuild is exercised through a supported character change.

No public runtime method, export, data field or declaration contract was removed or changed. The supported entry points and ownership rules are summarized in the [release notes](release-notes-v0.6.md#public-api-contract). Engine code still builds without editor usage; packed tests validate real imports/declarations and the actual independently installed consumer. Editor tests/helpers are internal APIs.

## Outstanding issues and risk assessment

**Release blockers:** human artist visual acceptance has not been completed. All automated gates have passing evidence; human acceptance remains required. A clean build alone is insufficient.

**Acceptable scoped limitations:** only fixture-backed version-1 compatibility; static PNG/WebP whole-image assets; stored editor ZIP imports for runtime preview rather than editable-session restoration; existing-skeleton rig authoring; two-link IK with documented scale limits; no timeline virtualization; browser/device coverage limited to local Chrome. Replacement image binaries remain session-only until saved in a package. These cases are documented and are not newly introduced failures.

**Publication prerequisites:** choose a license, fill package author/repository/license metadata, and decide registry/access/provenance before publishing. No license is selected on the owner's behalf. These are separate from the runtime/editor quality gates.
