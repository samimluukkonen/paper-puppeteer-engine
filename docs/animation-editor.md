# Visual Animation Editor — v0.5.2.8.3

Open `/animation-editor/` from **Open Animation Editor** in the demo or **Animation Editor** in the Rig Editor. The sample character loads with its default skin and its first animation (`idle`). The independent Rig Editor remains at `/rig-editor/`.

## Workspace

Animation selection, Undo/Redo, **Download JSON**, and save/validation status stay above the workspace. The preview and selection inspector share the upper area; the timeline spans the full width below. The canvas fits both dimensions of its host and frames the loaded artwork once, keeping the camera stable during playback and authoring.

Drag the divider between preview and timeline to resize them, or focus it and use Up/Down (Home/End selects the limits). Drag the edge of the track label column, or use Left/Right while that divider is focused. **Reset layout** restores panel proportions, label width, All tracks, and Fit zoom. These preferences do not edit animation data or enter history.

**Tracks** offers All, Keyed, and Selected. Events remain visible under every filter. Keyed hides empty properties; return to All to author them. Selected follows the selected bone. Filters preserve key selection and original row identities, including rectangle selection. Collapsed bone rows show read-only diamonds summarizing authored timing; expand a bone to edit its property keys.

**Zoom** offers Fit, 2×, 4×, and 8×. Zoomed timelines scroll horizontally while track labels stay pinned. The ruler, markers, playhead, scrubbing, and drags share the same time coordinates at every zoom level. Zoom and filters do not dirty the clip.

Selecting an event replaces the bone fields in the selection inspector, preserving the timeline's size and position. On narrow screens, **Inspector** opens a drawer; selecting a bone, key, or event opens it automatically. Close it with its Close button or Escape outside fields. Field Escape retains its existing draft-reset behavior. The drawer closes when returning to desktop widths, where the inspector is always visible.

**Clip settings** opens Mode, FPS, and the optional clip interpolation declaration. **Key details** in the inspector contains read-only outgoing interpolation information. **File tools** opens copy/log, import/paste, reload, discard, and revert operations. **Help** contains authoring guidance and timeline shortcuts. File tools and Help are modal dialogs: Escape closes them and editor playback shortcuts stay inactive inside them. Closing a dialog does not cancel an unfinished import form. Download JSON saves an exported file; it does not write into the project.

Select `idle`, `walk`, or another character animation in the Animation menu. Click the timeline or drag the ruler to preview its authored pose. Drag empty lanes to select keys. Pointer capture keeps scrubbing active outside the timeline; time clamps at both ends. Release, pointer cancellation, focus loss, or hiding the page ends scrubbing. Touch and pen use the same pointer path. Focus the ruler to scrub with Left/Down and Right/Up by 0.01 seconds; Shift increases the step to 0.1 seconds. Ruler navigation preserves selected keys. In the tracks, Left/Right nudge selected keys together while preserving spacing, or scrub when no keys are selected. Home / End navigate to the endpoints.

The sample `sword` and `guardUpperBody` clips contain baked arm rotations for a two-handed katana grip, so both show a complete sword-ready pose without IK. `sword` adds the idle body bob; `guardUpperBody` is the torso/arm overlay used while walking in the demo. The editor shows the default skin without the demo's katana prop; interactive weapon aiming and grip IK remain demo behavior.

**Play** starts or resumes at the current time. **Pause** holds time, playhead, and pose. **Restart** immediately returns to zero and preserves whether playback is active. **Home** does the same from anywhere outside typing controls; **End** remains timeline-only. **Space** toggles Play/Pause outside input, select, textarea, and content-editable regions; holding Space toggles only once. Focused buttons retain native Space activation (Restart rewinds, Loop preview toggles looping). Modified shortcuts and IME composition leave editor time alone. **Loop preview** toggles a transient editor preference (off by default). With it off, playback stops exactly at duration and holds the final pose. With it on, the editor wraps time and preserves overshoot, including deltas spanning several animation lengths. Scrubbing the ruler while playing temporarily suspends advancement; release, cancellation, lost pointer capture, focus loss, or page hiding ends the drag and resumes from the scrubbed time. Dragging while paused stays paused. Releasing at the final endpoint stops non-looping playback; looping playback wraps on the next update. An explicit Pause during a drag cancels resume. Pressing Play at the endpoint starts again at zero. Selecting another animation resets time and pauses. Controls are disabled without a valid animation. There is no separate Stop control in this milestone.

The ruler adapts to duration and available width, with major labels, minor ticks, and an end marker. The playhead and numeric time display reflect continuous seconds, formatted as `0.742 / 2.000 s` without rounding the internal clock. Metadata shows smooth/stepped playback, authored FPS for stepped clips, authored loop state, preview loop preference, speed, and current playback/scrub status. Preview loop and speed preferences persist across animation selection.

**Speed** offers 0.25×, 0.5×, 1× (default), 1.5×, and 2×. Each update advances animation time by elapsed real time multiplied by this editor-only speed. Changing speed while playing or scrubbing preserves time and playback intent; it never changes authored data, dirty state, or undo history.

**Mode** edits the animation's existing `playback` property in the working copy. Smooth mode samples the existing linear interpolation continuously. Stepped mode holds poses at authored FPS boundaries while the playhead stays continuous and Phaser continues rendering at its normal rate. Switching to stepped mode starts at 10 FPS; switching to smooth removes the FPS field as required by the schema. **FPS** is enabled only for stepped clips and accepts finite values from 1 to 240, including fractional rates. Existing clips with valid runtime FPS outside those editor bounds still load and preview unchanged. Invalid or empty edits show a validation error and restore the held value. Mode/FPS edits update the paused or playing preview immediately without retiming keys or events (the format stores their times in milliseconds).

The version 1 format supports only clip-level `interpolation: 'linear'`, with the same behavior when omitted. Smooth/stepped are sample-timing modes; keys and tracks have no interpolation settings. Mode/FPS edits change authored playback metadata, while preview speed and looping remain session preferences. See [Interpolation and sample timing](animation.md#interpolation-and-sample-timing) for runtime semantics and an example.

The interpolation authoring core exposes `state.authoredInterpolation`, `state.selectedInterpolation`, `state.getSegmentInterpolation(ref)`, and `state.setAuthoredInterpolation('linear' | undefined)`. Adding/removing the optional clip declaration changes authored data in one Undo/Redo transaction and preserves every key. Queries use the existing `KeyframeSelection` references in seconds and inspect authored metadata, independent of playback sampling. An outgoing segment runs from the requested property key to its next property key; interpolation belongs to the clip, not either endpoint. Last keys and one-key property timelines have no outgoing segment, even on looping clips.

**Selected key interpolation** in the timeline displays inherited **Linear** when every selected key has an outgoing segment. It displays **—** with an explanation for empty, missing or terminal selections. The inspector is disabled because version 1 has no per-key overrides; `state.setSelectedKeyframeInterpolation()` returns false and cannot silently edit the whole clip. Multi-selection across tracks remains uniform; a terminal member makes the whole selection unavailable under the existing query policy. Mixed authored modes cannot exist in this format.

**Clip interpolation** in the animation settings explicitly applies to the entire clip. Choose **Linear** to author the optional declaration, or **Default (Linear)** to remove it. Both produce the same pose. These metadata edits use `state.setAuthoredInterpolation()` in one history transaction, refresh the existing preview immediately, and preserve key values/times, current time and selection. Undo/Redo refreshes both controls. Selecting keys or opening a dropdown does not dirty the animation.

Filled diamonds identify outgoing Linear segments; hollow diamonds identify keys without an outgoing segment. Selection retains its color, ring and primary marker outline. Native marker titles show bone/property, time, value, and authored interpolation availability, independently of Mode/FPS sampling. There is no per-key smooth/stepped distinction to display in version 1. Pure APIs are documented in [Interpolation authoring verification](animation-editor-interpolation-verification.md); UI behavior, checks and the plan's schema limitations are documented in [Interpolation UI verification](animation-editor-interpolation-ui-verification.md). The v0.5.2.6.3 [hardening report](animation-editor-interpolation-hardening-verification.md) covers operation/history/runtime regressions. Selection queries prioritize missing keys over terminal keys regardless of selection order; a selection containing only existing keys is unavailable if any key lacks a successor.

**Undo** and **Redo** restore authored settings and keys through the existing snapshot history and refresh the preview. **Ctrl/Cmd+Z** undoes and **Ctrl/Cmd+Shift+Z** redoes outside typing controls, matching the Rig Editor. Input, select, textarea and content-editable regions keep their native undo behavior; consumed shortcuts, IME composition, Alt-modified combinations and held-key repeats do not replay authored history. Each Set Key/Delete Key click, Mode change, or committed FPS change records one logical edit. Intermediate numeric input events remain temporary. Unchanged/invalid edits preserve redo; a new authored change invalidates it. This editor owns its own bounded history of 100 snapshots, separate from the Rig Editor. Undoing back to the exact loaded/saved baseline restores clean state, including when history has branched. Redo restores dirty state when its data differs from that baseline. The original source remains immutable. Animation switching asks to discard unsaved changes; cancelling preserves the dirty working copy and reports the issue. Download first to retain edits. Every successful selection starts a clean history baseline. **Copy Animation JSON**, **Download JSON**, and **Log Animation JSON** export the same canonical committed versioned file. Successful copy, download start, or console logging establishes a saved session checkpoint, matching the Rig Editor. Serialization alone does not mark edits saved. Failed exports keep the previous checkpoint. A delayed clipboard write saves only its captured snapshot, so newer edits stay unsaved; stale completions from other sessions or older successful exports are ignored. It excludes temporary fields, selection, history, IK and facing. Downloaded filenames preserve the original character manifest filename (for example, the `sword` clip exports as `combat-idle.json`). Place the file in the folder referenced by its manifest path. Embedded editors without source paths fall back to a sanitized clip name. The editor does not write into the project automatically. **Discard changes** confirms before restoring the last downloaded/saved baseline (or the loaded clip if none was saved), resetting time and history. Canceling keeps edits intact. Failed downloads retain dirty state and display an error. Saved clips remain available when switching away and back within this session; a page reload reads the character files again.

Mode/FPS and committed key edits also protect page navigation, refresh, closing, and character selection with the browser's unsaved-change confirmation. Download committed edits, discard them explicitly, or undo them before leaving. Preview navigation and playback preferences do not trigger this confirmation.

Unsaved committed keys and settings also create a browser draft after a short pause and flush when leaving or hiding the page. Returning to an animation offers to restore its draft when the original clip and rig still match. Restoration remains unsaved and forms one Undo action. Temporary field values, selection, playback, IK, facing and history are excluded. Downloading, discarding, undoing to the saved baseline, or declining recovery removes the draft. Each character and animation has a separate draft; invalid, outdated, or incompatible drafts are rejected. Drafts are local to this browser and deployment path, with the latest draft shared between tabs for the same animation. Storage failures display recovery status and leave normal editing available. Continue downloading JSON to save your work in the project.

## Event clipboard and playback

With an event selected, the timeline buttons become **Copy Event** and **Duplicate Event**. Ctrl/Cmd+C copies the committed `{ time, name, data? }` record without changing data, history, dirty state, selection or time. Ctrl/Cmd+V / **Paste Event** creates a new event at the playhead and selects it. Payload presence, nested JSON and numbers are preserved. Identical same-time events remain distinct. One typed session clipboard holds the most recently copied event or keyframe group; paste follows its content even when another selection is active. Compatible animation switches retain it, and destination validation still applies. Input/textarea/content-editable controls retain native clipboard behavior.

Ctrl/Cmd+D / **Duplicate Event** shares cloning/paste and leaves the clipboard and playhead unchanged. Stepped clips use one authored frame; smooth clips use the timeline nudge step (0.01 s with None, 0.1 s with Frame). Forward duplication clamps to duration; at duration it steps backwards. No representable distinct destination means no operation. Paste and Duplicate each record one Undo snapshot, pause playback, select the new event and dirty only the working animation.

Normal playback calls the existing runtime event traversal on unquantized time: crossings include the new time and exclude the previous time. Large updates collect every crossed event, including multiple loops; equal-time events retain deterministic runtime order. Loop traversal includes the tail and the head before wrapping the editor clock. Zero-time markers fire once on initial Play, Play after completion and explicit Restart while playing. Pause/resume does not repeat them, including a pause at a wrapped zero. Restart while paused only navigates; the following Play fires start markers once. Scrubbing, ruler navigation, manually setting time, marker selection, authoring, recompilation and Undo/Redo emit no events. Scrub release resumes from the selected time without replaying crossed markers or start events.

Subscribe with `const unsubscribe = state.onAnimationEvent(event => { /* event.name, event.data, event.clip, event.layer */ });`. Notifications follow preview pose synchronization and use the runtime `FiredAnimationEvent` shape with layer `base`. The shared runtime dispatcher owns each listener's JSON payload and continues delivery after listener failures. Playback updates exceeding the runtime's 10,000-event limit, unsafe cycle bounds or finite clock arithmetic are rejected before clock/history changes or event delivery, with an editor validation message. Event-free clocks retain their existing large-delta wrapping behavior. Stepped FPS changes pose sampling without delaying event crossings.

The complete implementation and verification report is [Event clipboard, playback and hardening](animation-editor-event-hardening-verification.md).

## Visual bone keyframing

Select a bone from the **Bones** hierarchy or click its joint marker in the preview. The selected joint has an orange ring. **Show bones** controls the existing skeleton visualization; the hierarchy stays available when overlapping joints are hard to pick. Selection does not edit the animation or rig.

Tab enters the selected bone, or the first bone when nothing is selected. In the hierarchy, Up/Down select adjacent entries, Left selects the parent, Right selects the first child, and Home/End select the first/last bone. These keys retain the playhead time and never author joint values.

Scrub to a time, then inspect X, Y, Rotation, Scale X, and Scale Y. These are absolute bone-local authored animation values from the existing evaluator, before IK. Rotation is displayed and entered in degrees, then converted to radians for the animation format. Unkeyed properties fall back to the rig bind values; smooth and stepped evaluation match the existing preview. The numeric display uses six decimal places at most; **Set Key** without typing uses the full evaluated value, without rounding it to the display precision.

For example, at **0.5 s**, select `rightForearm`, enter **35** in Rotation, and press that row's **Set Key**. Typing previews a temporary editor-only transform, highlighted in yellow, and pauses playback at the held time. No key, history entry, or dirty change exists until Set Key. Set Key creates a sparse rotation key at 500 ms, or updates the existing rotation key within the core's floating-point time tolerance. Other properties are not implicitly keyed. You can also press Set Key directly to author the currently evaluated value. Each row shows **● keyed** or **○ no key**, using the existing keyed-state query API.

**Delete Key** removes only that property's key at the playhead, discards its draft, and immediately re-evaluates interpolation or bind fallback. Other properties and other times remain intact. A property commit clears only that property's draft; other pending fields remain temporary until individually keyed or cancelled. Empty/nonfinite input cannot be committed. **Cancel edits** or **Escape** restores all evaluated values and does not resume playback. Changing time, bone, or animation, pressing Play, changing authored settings, and undo/redo discard pending drafts. Preview preferences do not clear drafts. Undo/redo applies to authored keys through the existing snapshot history; navigation and drafts do not enter history. Creating/updating/deleting changed data marks the working animation dirty; no-op edits remain clean, and deleting newly created keys can restore the baseline.

**Facing** mirrors only the outer puppet container. **IK preview (fixed targets)** pins the configured character preview chains' current end joints in canonical puppet coordinates; targets project with facing and remain fixed while scrubbing/playing. The render pose can differ from the pre-IK inspector while IK is enabled. Neither preview preference edits authored values or dirty state, and Set Key never reads rendered joints, screen/world coordinates, or IK output. The Rig Editor's bind pose remains unchanged. Numeric editing is the authoring interface for this milestone; transform drag handles remain deferred.

Explicit time navigation and starting a scrub cancel drafts even when the playhead stays at the same time or clamps to its current endpoint. Restart at zero also cancels drafts. Undo/Redo cancel drafts even when their history stack is empty; cancelled fields refresh immediately, including focused fields. Other preview preferences retain drafts. Uncommitted FPS text is replaced by the held authored value when the working snapshot changes, so it cannot carry into another animation or a restored history snapshot.

Same-time movement keeps both events and stacks their committed markers. **Delete Event** or Delete/Backspace removes only the selected event, clears selection and records one operation. ## Keyframe markers and selection

Every authored property sample has a diamond on its expanded property lane. Sparse rows create markers only for their authored properties; evaluated poses, bind values and animation events never create markers. `PropertyTimelineTrack.keyframes` is an immutable array of `TimelineKeyframe` records (`boneId`, `property`, `time` in seconds, and `value`). It belongs to the cached row model, rebuilt from `workingAnimation` on authored changes or expansion. Markers and surviving DOM buttons remain stationary during playback; width changes reposition them with `timeToTimelineX()`.

Click a marker, or focus it and press Enter/Space, to pause playback, cancel drafts, select its bone/property and seek the sole editor clock to its exact authored time. A selected diamond has a contrasting color and `aria-pressed="true"`; the primary has a stronger outline. Selection uses frozen editor-only `KeyframeSelection` references (`boneId`, `property`, `time` in seconds). The immutable `selectedKeys` array is the whole selection, while `primaryKey` (also exposed as the compatibility getter `selectedKeyframe`) controls the bone/property inspector. Lookup uses the existing millisecond time tolerance and canonical authored times. Selection never dirties, serializes or enters authored history.

**Ctrl/Cmd-click** adds an unselected key or removes a selected key. It preserves the primary while that key survives; removing it chooses the first remaining key in selection order. Add/toggle never seeks, including when it needs a fallback primary. A normal click replaces the whole selection and seeks. **Shift-click** selects an inclusive range on the same property track, anchored at the last normal selection (or a surviving fallback anchor). Repeated Shift-clicks retain that anchor. Across tracks it adds the clicked key. Shift makes the clicked key primary and seeks; Ctrl/Cmd+Shift unions the range with existing selection.

Drag empty timeline lanes to show a transient **marquee**. Release selects marker centers inside its time and visible-row bounds across bones/properties. Ctrl/Cmd unions the result with the selection. Replacement retains the primary when included; otherwise it chooses the first result in visible track/key order and seeks once. Additive marquee never seeks. Scroll and resize use content-relative row geometry and the shared time conversion. Hidden/collapsed tracks are excluded. Escape, pointer cancellation, lost capture, blur, page hiding, session replacement, track-layout changes and authored mutations cancel the rectangle without changing selection. Playback pauses at the start and does not resume.

An empty-lane click clears keys and seeks, retaining bone/property context; Ctrl/Cmd-empty click retains selection and time. **Escape** cancels an active key drag or marquee first, and otherwise clears key selection. Bone/property navigation and successful animation switching clear all keys. Collapse retains selection. Ruler scrubbing and Home / End retain selection without forcing the playhead back.

**Delete Selected Keys**, Delete, or Backspace removes every selected property at its selected time, even after scrubbing away. Deletion pauses and cancels drafts but preserves the playhead time. Existing mutation APIs produce one snapshot/history transaction for the whole deletion, preserve unrelated keys, sparse siblings, events and source data, refresh preview/markers/indicators and clear selection. Shortcuts ignore typing controls, content-editable regions, composition and modified commands. Inspector value edits preserve selection. Reconciliation resolves surviving references through the shared tolerance, removes deleted keys and chooses a valid primary. Explicit time moves translate the full selection relative to the primary key. Dragging a selected marker moves the full group and makes that marker primary; dragging an unselected marker replaces selection and moves only that key. Undo/Redo reconcile the transient selection against restored authored data; they do not resurrect cleared selection. Undo after multi-delete restores every authored key in one operation.

**Previous Key** and **Next Key** navigate only the selected bone/property relative to current time, ignoring the held key within the shared tolerance. A destination selects and seeks exactly as a marker click does; unavailable directions are disabled. Group dragging and keyboard nudging are described below.

## Copy, paste and duplicate keyframes

**Copy Keys** or **Ctrl/Cmd+C** copies the entire selection into an internal editor clipboard. It preserves exact authored values and bone/property tracks. The earliest selected authored time is the anchor; each entry stores its offset from that anchor in milliseconds. Copy leaves the animation, dirty state, history, selection, drafts and playhead untouched. Copy with no selected keys retains the previous clipboard. The clipboard survives selection changes, scrubbing, playback, Undo/Redo and switching animations in the same editor session. Reloading or loading another character creates a new session.

**Paste Keys** or **Ctrl/Cmd+V** places the clipboard anchor at the current playhead. For example, keys at 0.5, 0.8 and 1.2 seconds pasted at 2 seconds appear at 2, 2.3 and 2.7 seconds. Original bone/property mappings remain intact; the active track does not remap them. Paste pauses playback, ends scrubbing, cancels drafts/dragging and refreshes the evaluator at the held playhead time. It replaces selection with the resulting canonical keys, choosing the earliest as primary (clipboard order breaks time ties).

The schema's explicit millisecond `duration` grows to include the latest pasted key, in the same history transaction as the keys. Keys are never clamped together at the endpoint. Loop, playback, events and interpolation remain unchanged. Interpolation is clip-level and supports only `linear` in the current format; there is no per-key metadata to copy, and pasting does not overwrite destination clip settings.

Paste follows movement collision policy. A single pasted key uses the closest same-bone/same-property key within the shared nanosecond tolerance as its canonical destination time, with stored-order ties. Multi-key paste retains every exact translated time and replaces external matching destination samples before inserting the entire group, as group movement does. Distinct nearby group members remain separate even within tolerance. Sparse siblings keep their original times and values. Repeated references to the same copied key are deduplicated. If floating point precision merges translated same-property identities, paste rejects the entire group without changing authored data or selection.

**Duplicate Keys** or **Ctrl/Cmd+D** copies the selection through the same group/paste logic and shifts it by one authored frame (`1 / playback.fps` seconds) for stepped clips. Smooth clips, including omitted playback metadata, use a deterministic 0.01-second step. This offset is independent of the Snap setting and does not snap off-frame authored keys. Duplicate preserves group spacing and the playhead, selects the result, extends duration when needed, and uses the same replacement policy on collisions. It keeps the user's clipboard intact.

Changed paste/duplicate operations each create one Undo action. Undo restores the complete previous snapshot, including replaced collision values and duration; Redo restores the exact result. Selection remains transient and follows existing reconciliation rather than being restored by history. Pasting identical authored data changes selection but adds no history, retains redo and leaves the saved baseline clean. Only the working animation changes; the source stays immutable.

Compatible cross-animation paste works even when destination property tracks are empty. Every entry's bone, transform property, time and value is validated against the destination rig/schema before installation. An invalid entry rejects the entire group, preserves authored data/history/selection, and displays the validation error in the existing status area.

Clipboard shortcuts require focus in the **Animation timeline** panel (lanes, markers or its command/playback buttons). Elsewhere, Ctrl/Cmd+D retains the browser bookmark behavior. Inputs, numeric fields, selects, textareas and inherited content-editable regions retain native editing; IME composition, Alt/Shift modifications and consumed events are ignored. Held shortcut repeats are prevented in timeline context without executing again. The buttons remain available for mouse/touch use and are disabled when their command has no selection/clipboard/animation.

## Data and preview ownership

`AnimationEditorState` is independent of Phaser and the DOM. Its internal `AnimationEditorSelection` owns transient bone/property/key selection, transform drafts, expansion, and cached timeline rows. The state facade coordinates notifications, playback, validation, authored edits, and history through the existing public API; history snapshots contain only authored animation data. It owns a frozen source snapshot and saved baseline per animation and a working animation in the existing versioned file format. Selection reuses the frozen saved snapshot; edits replace changed branches, preserving immutable source data and cached validation/compilation. `markSaved()` retains the selected animation's working data across selection changes while keeping its original source untouched. Explicitly discarding changes restores the last saved baseline on the next selection. Caller-owned character animations remain untouched. Editor-only selection, time, playback, speed, preview loop preference, scrubbing, validation issues, and history stay outside the serialized data. Authored FPS/mode use the existing `playback` union; no schema or engine changes are needed. `subscribe()` connects external state changes to the preview and UI.

`currentTime` exposes the sole continuous editor clock in seconds; internally it retains authored milliseconds so event boundaries remain exact. `AnimationEditorScene.update()` converts Phaser's elapsed milliseconds to seconds and calls `advancePlayback()`. Rendering runs at the normal Phaser rate; pose quantization remains the evaluator's responsibility. `duration` reads the working animation's explicit `duration` in milliseconds and converts it to seconds; keys and events do not redefine the endpoint. Zero-duration clips are invalid in the existing runtime schema and display its validation errors. Empty/partial tracks and event-only clips retain their explicit positive duration. No character, no animations, or no selection uses a disabled zero-length timeline. Nonpositive or nonfinite playback deltas do nothing, and completed playback sends no further time notifications. Looping traverses the unwrapped interval before reducing the clock modulo duration. Event catch-up uses the runtime budget and rejects unsafe arithmetic before advancement. Event-free loops retain finite overflow fallback: if scaling or addition overflows, reduce the distance (or real time) by one preview loop before wrapping. The zero-length guard runs before modulo; empty or rejected zero-duration clips hold time at zero with playback stopped.

`TimelineController` owns pointer capture and measured DOM width, generates the ruler through pure helpers, and translates pixels into calls to `setCurrentTime()`. It calls `beginScrub()` on pointer-down and `endScrub()` on release or interruption, and releases a captured pointer when selection clears the scrub state. It has no independent animation clock. `buildTimelineTracks()` produces immutable discriminated bone/property rows from the shared hierarchy traversal, runtime property list, authored-key query and expansion set. `AnimationEditorState.timelineTracks` caches rows until expansion or the working snapshot changes. `TimelineTracksController` reconciles corresponding labels and lanes, retaining surviving DOM elements and updating selection separately. Playback and scrubbing do not rebuild track layout. Row expansion and property selection never enter animation JSON or authored history.

`AnimationEditorPreview` and inspector value queries share compiled clips through `getCompiledPreviewClip()`, cached by fully frozen working animation and rig identity. Each retains independent pose buffers; mutable inputs are validated and compiled fresh. The preview owns an existing `AnimationPlayer` over the puppet's joints. The compiled preview uses `loop: false` and an empty event list without changing source or working data, so the evaluator also samples the exact final pose for stepped clips whose endpoint falls between frames. It converts seconds to milliseconds and calls `sample(..., { mode: 'playback' })`, then `Puppet.syncPose()` projects the pose through the runtime rendering pipeline. This reuses interpolation, shortest-path rotations, and stepped sampling; timeline code never interpolates bones. Each changed pose sample resets joints to bind pose before evaluation, preventing untracked temporary values from leaking after cancellation or navigation. Temporary local properties apply after evaluation and before pose presets/IK, while preserving optional IK configuration and pose presets. The page configures optional demo IK chains, disabled by default, and a facing preference; these affect only rendering. Embedded previews with enabled IK or mirroring retain the runtime order: evaluator, pose presets, constraints/IK, and rendering. Facing mirrors the outer puppet container without editing local animation transforms. Scrubbing and editor playback neither advance runtime playback clocks nor dispatch animation events; stripping markers also suppresses time-zero events on initialization, selection, authored settings edits, and undo/redo. Runtime gameplay events remain unchanged.

`replaceWorkingAnimation()` validates external authored changes with the existing JSON/schema/reference checks and owns a fresh frozen copy. Internal FPS/mode setters validate their scalar changes; keyframe setters use the validating mutation helpers. These internal edits retain unchanged frozen tracks, rows, events, and playback settings instead of copying the whole clip again. All edits record one replacement through the shared `SnapshotHistory`, preserving those shared branches through undo/redo. Invalid replacements preserve the held working copy and pose. Replacements must retain the selected animation’s name; renaming is deferred. Dirty state compares the working snapshot with a saved baseline, following the Rig Editor pattern. `exportAnimation()` returns a success result with canonical JSON/data or validation issues; `exportJson()` is the compatible throwing wrapper. Both validate and serialize committed data without changing state. Export controls call `markSaved(snapshot)` only after their destination succeeds. The save baseline retains undo history, while `undo()` and `redo()` are exposed for authored edits. `selectAnimation()` refuses dirty replacement unless explicitly called with `{ discardChanges: true }`. Scrubbing and selection never record history.

`previewLoop`, `playbackSpeed`, and `isScrubbing` are transient state views. `isPlaying` retains playback intent during a ruler scrub, so `advancePlayback()` skips while `isScrubbing` and resumes naturally after `endScrub()`; no separate saved playback flag is needed. Successful animation selection clears both playback and scrub state and resets time before notifying the preview. Failed selection preserves the held session. Binding a new session, disposal, and scene shutdown pause before ending a scrub, preventing accidental resume.

Playback commands, loop toggles, scrubbing, and time advancement never change animation snapshots, dirty state, or authored history. Existing dirty edits remain dirty. Replacements and history restoration that shorten duration clamp time and pause if the endpoint is reached.

For a custom character, pass `{ characterUrl: '../characters/hero/character.json' }` as the third constructor argument of `AnimationEditorScene`. It uses the shared cancelable character loader, existing manifest validation, and default skin. Failed loads show errors; scene shutdown invalidates pending loads, pauses and releases editor playback, disposes the preview subscription/player, and destroys the puppet.

## Moving keyframes

Drag a selected diamond horizontally to move every selected property on its existing bone/property lane, across any number of bones. The clicked marker becomes the primary/anchor; an unselected marker replaces the set before dragging. Vertical pointer motion never changes tracks. All group markers follow a provisional common delta and the sole playhead follows the anchor; preview and inspector evaluate the unchanged working animation at that time until release. Release commits the move once, selects every translated authored key time, and immediately refreshes markers, keyed indicators and the runtime evaluator. Playback pauses at pointer down and remains paused after release or cancellation. A click without movement only selects; a 3px movement threshold prevents accidental retiming.

**Snap → None** (default) keeps continuous seconds. **Snap → Frame** rounds to the nearest frame with `Math.round(time * fps) / fps`, using stepped clips' authored FPS and a shared 10 FPS fallback for smooth clips or unavailable/invalid FPS. Both endpoints remain reachable even when duration is off-frame. Snapping never retimes the rest of the clip or enters history. Hold **Shift** during dragging to bypass snapping. Selected-key **Left/Right** nudges by one snapped frame or 0.01 seconds with snapping off; **Shift+Arrow** uses ten steps. These shortcuts ignore typing fields, consumed events, composition and Ctrl/Cmd/Alt combinations.

The group delta clamps to `[-earliestTime, duration - latestTime]`. Individual keys are never clamped or snapped separately, so spacing survives both boundaries. The duration does not grow during movement (paste may extend it). Frame snapping applies only to the anchor before deriving/constraining this common delta; a boundary wins over snapping when they conflict. Moving onto an existing key on the same bone/property replaces its value with the moving key's value. Matching uses the shared nanosecond tolerance. A single-key collision keeps the nearest destination's canonical authored time, as before. A group keeps exact translated times and replaces external matching properties at those times; independently canonicalizing each destination would distort spacing. All selected sources are removed before collision checks, and all external replacements happen before inserting the group, avoiding both original-position self-collisions and collisions between distinct selected times within tolerance. All other matching destination samples for that property are removed, preventing duplicates. Other properties in either sparse row retain their times/values; empty rows are removed and the bone's rows remain sorted. Interpolation is clip-level in the current schema and is preserved, along with events/playback settings and other bone tracks.

The original authored snapshot stays untouched during dragging. **Escape**, pointer cancellation, lost capture, focus loss, page hiding, navigation, selection, track collapse, settings edits, history restoration and rebinding cancel provisional movement. Cancellation restores the original group and primary and returns the clock to the original anchor time, keeps playback paused and preserves authored data, dirty state, history and redo. An unchanged gesture or endpoint nudge adds no history entry. Invalid/missing targets and destination times whose floating-point precision cannot preserve distinct keys reject the entire move without authored or selection changes. A committed drag or changed nudge records one immutable `SnapshotHistory` entry; Undo/Redo restores exact prior/result snapshots, including collision replacement. Selection remains transient under the existing history policy: history validates it and clears a time that no longer exists rather than restoring past navigation.

`TimelineController` owns pointer capture on the stable timeline container and measures its current client rectangle for every pointer conversion. Scrolling and resizing during a drag re-evaluate that rectangle. `TimelineTracksController` only positions all provisional selected markers with the existing `timeToTimelineX()` helper. No extra clock, animation copy, DOM-owned data mutation, world-space or IK baking is introduced.

## Keyframe authoring core

v0.5.2.3.1 adds pure data operations in `keyframes.ts` and commands/queries on `AnimationEditorState`. v0.5.2.3.2 connects these existing APIs to the visual inspector without changing their signatures. v0.5.2.3.3 hardens cancellation boundaries, integrates keyboard history and expands regression verification. v0.5.2.4.1 adds bone/property timeline tracks and transient track navigation. v0.5.2.4.2 adds authored markers, single-key selection, selected deletion and previous/next navigation. v0.5.2.4.3 adds time movement, provisional dragging, snapping, keyboard nudges and timeline hardening. v0.5.2.5.1 adds selection sets, primary context, additive/range/marquee selection and atomic multi-delete. v0.5.2.5.2 adds an internal clipboard and atomic paste/duplicate. v0.5.2.5.3 completes group dragging/nudging with shared boundaries, snapping and atomic collision replacement. Package version: `0.5.2-5.3`.

The existing file format remains authoritative: `tracks[boneId]` holds a strictly time-sorted array of sparse `{ time, x?, y?, rotation?, scaleX?, scaleY? }` rows. Time is milliseconds, rotation is radians, and values are absolute local transforms. Each property has its own independent samples even when several properties share a row. Setting rotation never authors position or scale implicitly.

Pure mutation signatures are:

```ts
setBonePropertyKeyframe(animation, rig, boneId, property, timeMs, value)
removeBonePropertyKeyframe(animation, rig, boneId, property, timeMs)
moveBonePropertyKeyframe(animation, rig, boneId, property, fromTimeMs, toTimeMs)
```

Both return a replacement animation, preserve supplied version/metadata, and never mutate or freeze the input. Changed arrays/rows are copied; unrelated branches are shared and should be treated as read-only. No-op edits return the input identity. They guard rig references, supported properties, finite values, and duration bounds, and validate both input and result through the existing file validator. Invalid inputs throw. Existing invalid/unsorted timelines are rejected rather than silently repaired.

Setting a property first looks for its nearest authored key within `KEYFRAME_TIME_TOLERANCE_MS = 1e-6` milliseconds (one nanosecond). It updates that value while retaining its stored time. If the property is absent, it merges into the nearest row in tolerance or inserts a new sorted row. Equal-distance matches favor the earlier stored row. Existing distinct close rows are retained; new edits do not add effectively duplicate times. The same `keyframeTimesMatch()` policy applies to lookup, deletion, and keyed-state queries. No FPS quantization or global rounding changes authored time. Endpoint arithmetic error within tolerance is clamped to zero/duration; times farther outside the duration are rejected.

Deleting removes only the requested property. Rows with no remaining transform values are removed; tracks with no remaining rows are omitted. Other bones, properties, key times, events, and playback metadata remain intact.

Pure queries are `findBonePropertyKeyframe(animation, boneId, property, timeMs)` (a detached `{ time, value }` or `undefined`), `hasKeyframeAtTime(...)`, and `getKeyedPropertiesAtTime(animation, boneId, timeMs)` (in runtime property order). Missing keys and nonfinite query times produce an empty result.

`getEvaluatedBonePropertyValue(animation, rig, boneId, property, timeMs)` uses the runtime pose buffer and playback quantization, compiling an event-free, nonlooping preview clip. `getEvaluatedBoneTransform(animation, rig, boneId, timeMs)` reads all five local properties together. Fully frozen animation snapshots cache compilation per rig and reuse pose evaluation within the same sampled frame; mutable or shallow-frozen caller data is validated and compiled afresh. Returned transforms are detached copies. Sampling never advances a clock or stores an evaluated pose as authored data. Smooth interpolation and shortest-path rotation come from the runtime; stepped clips hold at authored FPS boundaries and retain the exact endpoint. Before the first property key and after its last, the runtime holds the nearest value. A wholly unkeyed property falls back to the rig bind pose. Results represent the animation's local transform before optional presets, IK, and facing. Invalid evaluation targets throw.

The v0.5.3.1 [ghost pose sampling foundation](ghost-pose-sampling.md) extends this sampler with `getEvaluatedAnimationPose(animation, rig, timeMs)` for complete detached local poses. `state.sampleGhostPose(timeSeconds)` samples any in-range authored time; `state.sampleGhostPoses(settings?)` returns previous/next frame samples from the current working copy without changing the playhead or preview. The [multi-ghost artist controls](onion-skin-controls.md) display these samples through the **Onion Skinning** checkbox above the preview. Open **Onion settings** to choose 0–3 poses per direction, 1–5 authored frames of spacing, independent opacity (0.05–0.6) and previous/next colors. Set a count to zero to hide that direction. Defaults remain one cool previous and one warm next pose at 22% opacity behind the current puppet. Spacing follows authored stepped FPS or the 10 FPS fallback; out-of-range neighbors are omitted. These transient scene preferences leave dirty/history/exports unchanged, and ghosts show authored poses before procedural IK and temporary inspector drafts.

State methods use **seconds**, defaulting to `currentTime`:

```ts
state.setBonePropertyKeyframe(boneId, property, value, timeSeconds?)
state.removeBonePropertyKeyframe(boneId, property, timeSeconds?)
state.findBonePropertyKeyframe(boneId, property, timeSeconds?)
state.hasKeyframeAtTime(boneId, property, timeSeconds?)
state.getKeyedPropertiesAtTime(boneId, timeSeconds?)
state.getEvaluatedBonePropertyValue(boneId, property, timeSeconds?)
state.getEvaluatedBoneTransform(boneId, timeSeconds?)
```

The returned keyframe's `time` remains milliseconds. Mutation methods return success, including no-ops; invalid edits return `false` with validation issues and leave the working snapshot/history unchanged. Without selection, mutations return `false`, key/value lookups return `undefined`, and keyed-state queries return `false`/`[]`. Evaluation errors on a selected animation throw without changing session diagnostics.

Only `workingAnimation` is replaced. Actual data changes record one history entry, update the existing dirty comparison, and notify the existing preview subscription, which refreshes immediately while paused. No-ops preserve snapshot identity and redo history. Deleting newly created keys can return the animation to its clean baseline. Queries never notify or change history, validation issues, or dirty state. Edits preserve continuous time and playback intent; the clock architecture is unchanged.

For example, explicitly key the value visible at a paused playhead:

```ts
const value = state.getEvaluatedBonePropertyValue('head', 'rotation');
if (value !== undefined) state.setBonePropertyKeyframe('head', 'rotation', value);
```

## Stable animation export (v0.5.2.8.1)

`animationSerialization.ts` owns the only export serializer: `serializeAnimation(input, rig): AnimationExportResult`. It uses the existing `AnimationJsonDefinition`, file format version 1, and `inspectAnimationDefinition()` before projecting data and again on the output. Invalid input returns `{ success: false, issues }`; valid input returns `{ success: true, data, json, issues }`. No export-only schema or runtime/package API changes are introduced. The original source, working snapshot, editor navigation, drafts, clipboard and history remain untouched.

JSON uses two-space indentation and a trailing newline, matching rig export. Top-level fields follow a fixed readable order; bone IDs and payload object keys use locale-independent lexical ordering. Keyframe fields follow the engine transform property order. Valid keyframe arrays already have strictly increasing times and retain that order; invalid or duplicate key times are rejected rather than sorted or repaired. Events use the runtime's stable chronological ordering, retaining authored order and multiplicity at equal times. Optional fields, empty/partial tracks, linear interpolation metadata, authored loop/duration and smooth/stepped playback settings remain present as authored.

Numeric cleanup reuses `roundEditorNumber()` for six-decimal candidates but accepts a change only within four relative machine epsilons. It removes arithmetic noise such as `0.30000000000000004` without truncating meaningful precision, rounding tiny nonzero values to zero, or quantizing times to FPS. Duration, key/event times, transform values and FPS share that policy. A shared time map preserves distinct nearby authored times and endpoint relationships. Event payload numbers are preserved exactly; their meaning belongs to the application.

Clipboard failures offer Download and Log alternatives. Download filenames retain manifest basenames, with a sanitized animation-name fallback and `animation.json` when no name is available. Copy/download/log establish session checkpoints and retain Undo/Redo history; they do not overwrite source files. Saved authored snapshots retain their original precision. A page reload still reads character assets.

See [export verification](animation-editor-export-verification.md) for automated coverage and human checks. File dropping, mirrored tools, IK target animation and baking remain deferred to v0.5.3+.

## Animation import and reload

**Import / Paste Animation JSON** opens a text area with **Parse / Import** and **Cancel**. **Import local animation JSON** reads a local `.json` file through the same pipeline. Load a character first: its rig supplies bone-reference validation. The file must have supported animation `version: 1`; unknown bones, unsupported versions, syntax errors and invalid authored data produce field-path diagnostics before replacement.

After validating and confirming any dirty replacement, successful import replaces current edits, registers/selects the imported clip name, creates independent immutable source and working snapshots, and establishes a clean baseline. Undo/Redo history, bone/property/key/event selection, transform and inspector drafts, drags, scrubbing and marquee state reset. Playback pauses at zero, and timeline/preview subscribers immediately rebuild using the existing runtime evaluator. Import does not fire events. Bone expansion, clipboard contents, speed, loop-preview and snapping preferences persist for the loaded rig. Rejected imports update diagnostics while retaining authored data, history and transient session state.

**Reload Current Export** serializes committed authored data and runs the same import path. It normalizes export floats and creates a fresh clean session without downloading or firing events. Dirty import/reload requires confirmation after validation; cancelling retains the current session. Download first if you need to retain previous edits. Imported clips remain available in this in-memory session; importing does not change the character manifest or write files. File reads superseded by another import, session change or controller disposal are ignored; edits during a pending read require choosing the file again.

Development APIs: `importAnimationJson(text, rig)` returns a discriminated result containing a validated frozen snapshot or structured issues. `state.importJson(text)` and `state.reloadCurrentExport()` return success booleans and coordinate session reset. `verifyAnimationRoundTrip(input, rig)` compares canonical export → import → export JSON and original/reloaded evaluated poses. It returns `equivalent`, `posesEquivalent`, `playbackEquivalent`, representative `sampleTimes` in milliseconds, both JSON strings and the imported snapshot. `compareEvaluatedAnimationPoses(original, reloaded, rig)` uses the same runtime compiler, evaluator and playback quantization for direct dev/test comparisons. These are editor APIs; engine file formats and runtime evaluators remain unchanged. See [import verification](animation-editor-import-verification.md).

## Production animation workflow

1. Open the Animation Editor and choose a character and animation. The session status names the animation and shows **Clean** or **Modified**, using the document's dirty state.
2. Scrub the ruler to the desired time, select a bone in the hierarchy or preview, and choose a property track. Field edits are temporary previews; **Set Key** commits that property and **Delete Key** removes it.
3. Adjust timing with marker dragging, range/marquee selection, group movement, nudges, snapping, copy/paste or duplicate. Undo/Redo operates on authored changes only.
4. Inspect outgoing interpolation and use **Clip interpolation** for the supported Linear declaration. Choose Smooth or Stepped playback and FPS to preview sampling behavior. Version 1 supports no per-key interpolation overrides.
5. Add events and edit time, name and optional JSON data. Preview playback dispatches crossed markers; scrubbing, import and revert stay silent.
6. Preview with play/pause, restart, loop and speed. Facing and fixed-target IK preview do not change animation JSON. Check **Validation: OK**; every export validates again.
7. **Download JSON**, **Copy Animation JSON**, or **Log Animation JSON** exports committed keys, events and settings. A successful destination marks that exported snapshot clean, matching Rig Editor. History remains available; undoing away from the checkpoint becomes Modified. A delayed clipboard completion leaves later edits dirty. A failed export never saves.
8. Use **Reload Current Export** for a fresh export/import of the current committed animation, or import the downloaded file. Both reset history and pause at zero; dirty replacement requires confirmation. Reload includes edits since the last download. For visual and runtime verification, follow [production verification](animation-editor-production-verification.md).
9. Place the download in the character folder at the manifest's animation path (for example `animations/walk.json`). Add that path to `character.json` if necessary. Normal CharacterLoader/Puppet playback uses the exported file directly: `puppet.play('walk')`. Saving a session checkpoint does not write project assets; a page reload reads those assets again.

**Rig Editor = skeleton/joint/artwork alignment. Animation Editor = motion over time.** Normal keyframing edits absolute local animated transforms, not the bind-rig structure. Change skeleton, joint alignment, sprite offsets/origins or slots in Rig Editor before authoring motion.

## Session lifecycle and recovery

The loaded/imported source remains immutable. The working animation changes through immutable authored snapshots. Dirty compares working data to the current saved checkpoint; no DOM controller computes its own dirty state. Load/import is clean, edits are Modified, Undo to the checkpoint is clean, and Redo away from it is Modified.

**Discard changes** confirms before returning to the last successful export checkpoint. **Revert Animation** returns to a fresh clone of the loaded/imported source, including changes already exported. Revert uses the session source without fetching assets. It resets the saved checkpoint, history, drags, drafts, bone/property/key/event selection, scrubbing and time; playback pauses at zero and timeline/preview refresh. Revert remains available when clean, because the exported checkpoint can differ from the source. Dirty revert requires confirmation. Import establishes a new source for future reverts.

Switching animations confirms dirty replacement and starts fresh history, preserving saved checkpoints for other clips. Invalid or cancelled selection/import/reload/revert retains authored edits. Import validates before asking to discard; empty files, syntax errors, wrong document shapes, unsupported versions and invalid schema data report diagnostics. Pending file reads and clipboard completions cannot replace a newer selected/imported/reverted session, including switching away and back to the same animation. Page navigation, character selection, refresh and closing retain the existing browser unsaved-change prompt and local draft recovery.

External animation version 1 uses the shared strict file schema: unknown fields at the clip, key, event or playback level are rejected, not stripped. Every supported field is preserved even if no editor control exposes it. Arbitrary valid JSON event payload fields remain supported. Empty tracks/events and a single key are valid with positive duration. Zero duration is rejected safely by the existing runtime schema; the editor does not invent a separate zero-duration format.

Import/export adds no global shortcuts. JSON text areas keep native copy/paste/undo and typing; Ctrl/Cmd+C/V/D affects authored keys/events only with focus in the timeline. Space/Home, modifiers and IME retain their existing typing guards. Use the import/export buttons for documents.

Editor-only APIs added in this hardening pass: `revertAnimation({ discardChanges?: boolean })`, `sessionRevision`, and optional `AnimationImportOptions.confirmDiscard` on `importJson`/`reloadCurrentExport`. The callback runs only for valid dirty replacement. Direct callers without a callback retain the existing explicit replacement behavior and should provide their own confirmation when appropriate. No public engine API, schema, evaluator or dependency changed.
