# Local autosave and crash recovery (v1.0.2)

The Project Workspace, Rig Editor, Animation Editor and Scene Editor retain complete local drafts in IndexedDB. This is browser storage, **not a file save or backup service**. Export a project or character ZIP for a portable disk copy. Clearing site data also clears recovery drafts.

Committed authored changes are checked every 500 ms and saved after a 1-second debounce. Open rig field/drag operations, animation key/event/IK gestures, uncommitted animation transforms, artwork proposals/imports and scene Actor/action gestures block capture. Playback, scrubbing, selections, camera settings, guides, temporary textures and other preview/UI state do not change the authored fingerprint. Hidden-page flushing is best effort. An unexpected close can lose changes since the last completed local save; it cannot finish an asynchronous package build reliably during unload.

## Ownership and consistent capture

Draft preparation times out after 60 seconds; each artwork request, including its response body, has a 30-second deadline. Failed or timed-out preparation keeps the previous saved revisions and offers Retry. Discard, page suspension and disposal cancel preparation promptly, including host operations that ignore cancellation; late results cannot write a draft. An already-dispatched storage transaction still settles before Discard removes its revisions.

`ProjectWorkspace` remains the project metadata owner. The retained character editor owns its rig, skins, animations and artwork; `SceneEditorDocument` owns scene working copies. Autosave reads those owners without ending gestures, marking exports, changing Undo/Redo or installing snapshots. Switching project/editor views retains these owners and each project's autosave controller.

`buildProjectDraft` captures project metadata, character revisions, scenes and binary references synchronously before asynchronous reads. Character serializers retain completed revisions and reuse unchanged immutable document bytes; scene JSON is cached by its authored fingerprint. Project source artwork has already passed import validation and is reused directly. Standalone source artwork and replacement Blobs are read and validated once per definition/Blob, then reused across edits. Changed mutable input is detached before I/O, failed/cancelled asset reads are retried, and image membership changes invalidate cached image snapshots. Package/path/JSON/image budgets still apply to each complete draft.

Standalone character drafts serialize directly into the portable project recovery layout, without registering a temporary project or preparing an export. Project autosave uses the same layout and serializes only changed character/scene revisions. Metadata validation is cached by authored revision, so broken character or scene dependencies cannot replace recoverable drafts. Complete package validation and repeated browser decoding remain on explicit export and recovery boundaries. Standalone scene drafts wrap all retained scenes and their character dependencies through the project packager. Replacement/imported artwork contributes its immutable Blob bytes; no draft references temporary Blob URLs.

## Persistence format and retention

Standalone scene recovery merges equivalent character packages even when their manifest references differ. Distinct packages sharing a character ID receive unique `-recovery-N` IDs in the detached recovery project, with Actor references remapped to their own package. Original scene snapshots and character definitions retain their authored identities.

Database: `paper-puppeteer-recovery`, database version **2**.

- `revisions`: lightweight records keyed by revision UUID, with a document `key` index. New records have `version: 2`, `id`, `key`, `name`, `savedAt`, the authored `revision` fingerprint, and `files: [{ path, digest }]`.
- `binaries`: immutable Blobs keyed by their SHA-256 digest, shared across paths, revisions and projects. JSON documents are canonical UTF-8 package files; image/audio files contain actual binary data.
- `references`: one `{ id, digests }` record per new revision, with a multi-entry `digest` index. Each digest occurs once per revision, even if several paths share it. Indexed counts retain a binary until its last revision reference disappears.
- `drafts`: original version-one envelopes retained during upgrade. The upgrade copies their lightweight metadata into `revisions` without copying or rehashing Blobs. Compatible envelopes are removed as newer saves supersede them; corrupt/incompatible envelopes remain available for explicit recovery/discard.
- `leases`: `{ key, owner, expires }` records for exclusive autosave writers.

Save queries only the current document's metadata through its key index; the project limit uses a key-only cursor over distinct project keys. Listing reads metadata only, and Discard selects revision IDs through the key index. Content-addressed binary existence checks use keys without reading stored Blobs. Reused package byte arrays retain weakly cached digests and owned snapshots; byte comparisons detect mutable callers, while snapshots isolate changes during hashing. Blobs are created and inserted only for missing digests.

A read/write transaction checks/renews the lease, inserts revision metadata, references and any new binaries, then prunes superseded revisions and binaries with zero references together. Interrupted or quota-failed transactions leave previous revisions and their references intact. Validation and hashing happen before that transaction; recovery still verifies every resource digest. Existing package/path/JSON/image budgets remain in force.

Keep **two complete revisions per local draft**, across at most **ten local draft keys**. New draft keys beyond that limit fail with a cleanup instruction; they do not evict someone else's newest draft. Incompatible envelopes are preserved rather than automatically pruned. The recovery dialog lists individual revisions, allowing selection of the preceding revision when the newest cannot be restored. Export never deletes recovery data.

Use **Discard local draft** on the active editor/project to remove that key's revisions and pause its autosave. Use **Retry / Resume local saving** to re-enable it. The **Recovery drafts** dialog can discard obsolete projects, including drafts declined with Cancel. Discard Draft removes all revisions of the selected key. Active foreign leases prevent deletion.

## Startup and recovery

Each authoring route checks for recovery records on startup. Controls sit below the shared application header; Recovery drafts is hidden when no drafts exist, and availability updates after saves/discards and window focus. The compact dialog follows the [GitHub/Primer style guide](style-guide.md). The dialog shows the project name, actual local-save timestamp and revision selector, with **Recover Draft**, **Discard Draft** and **Cancel**. Cancel preserves storage and continues ordinary startup; Recovery drafts opens the dialog again.

Recovery reads and verifies every file digest and validates the entire project, including scene dependencies and binary images, before installing anything. It opens a detached project working copy and marks it unexported. Original imported files are never overwritten. Accepting recovery in a standalone editor records a one-time, same-tab recovery intent for the selected revision and navigates to the Project Workspace. The Project Workspace consumes that intent and restores the draft without asking again; validation/ownership failures keep the recovery dialog available with an error. A later independent startup offers recovery normally. Runtime previews recreate disposable object URLs and reuse the existing Phaser texture/resource cleanup paths.

Unknown envelope versions, malformed metadata, corrupt bytes, missing assets and invalid packages produce an actionable message while preserving stored data. Select the other revision or explicitly discard the obsolete draft. Storage denial/unavailability, quota errors and concurrent owners show **Autosave failed** with instructions to export, resolve the problem and retry. Local saving has independent Unsaved changes / Saving locally / Local draft saved / Autosave failed status. Successful explicit project/scene exports are labelled separately; ordinary browser autosaves never mark export checkpoints.

## Multiple tabs

Each autosave controller has a random owner ID. Web Locks hold exclusive browser ownership and release automatically when a document closes or crashes. An acquired browser lock permits immediate recovery over a stale IndexedDB lease after refresh. Lease claims, writes and deletes also use IndexedDB transactions. Leases renew every five seconds and expire after fifteen seconds; these leases provide the fallback in browsers without Web Locks. `pagehide` releases ownership and `pageshow` resumes monitoring. If artwork hashing was already in flight during suspension or unmount, the autosave owner releases again after that operation settles, preventing a late write from retaining the old editor's lock. Disposed owners cannot restart timers. Without Web Locks, a crash that prevents release can require waiting up to fifteen seconds before retrying recovery. A resumed stale tab must re-acquire the lease before writing and reports a competing editor session instead of overwriting its draft. Project keys use stable project IDs; standalone characters share a key across the rig/animation routes; standalone scene sessions share a route key.
