# Rig editor

[All guides](../README.md#guides)

External character loads, rig file imports, and recovered browser drafts allow at most 4096 bones
and 256 hierarchy levels (including the root), 4096 slots, 4096 attachments, and 256 IK constraints,
in addition to JSON byte limits. Rejection preserves
the current editor session. Custom hosts can raise `maxBones`, `maxBoneDepth`, `maxSlots`, `maxAttachments`, and `maxIKConstraints` when loading trusted
characters; development adapters can pass work limits as the fourth `createSessionController` argument.

Local rig JSON imports have a 10 MiB size limit. Oversized files are rejected before reading,
and failed imports preserve the active session and its undo history.

Open `/rig-editor/` from the header's **Rig Editor** link. The editor loads the sample character with its default skin and shows its canonical bind pose in right facing. Select bones by clicking joints or their parent lines, or use the hierarchy. Select slots by clicking their square markers or hierarchy entries. Hold Alt while clicking when a slot overlaps a joint.

Use **Attachments & skins** to assign or clear slot artwork, create stable attachment IDs, select skins and author partial overrides. The panel shares inspector selection and rig Undo/Redo. Embedded changes export with the rig; edits to manifest skin files use **Download skin JSON**. See [visual attachment and skin management](visual-attachment-skins.md) for the workflow and save/reload rules.

Expand **Character package** above the command bar to download the complete validated character ZIP, including applied sprite replacements, and reload/import it into an isolated production runtime preview. Individual JSON downloads retain their existing checkpoints and file placement workflow. See the [complete artist and package workflow](artist-workflow.md).

Use the header's **Character** selector to load either the demo puppet or the artist's **Random paperdoll sketch**. The sketch also opens directly at `/rig-editor/?character=random-paperdoll-sketch`. Navigation between Rig Editor and Animation Editor keeps the selected character. Switching characters uses the same unsaved-edit protection as leaving the editor.

The viewport workspace matches the Animation Editor: the package controls, compact command bar, and scrolling inspector occupy the left column. The A4 portrait preview (210:297) fills the right side from below the header to the bottom of the workspace. Drag the divider to resize the columns, or focus it and use Left/Right; Home/End select the limits. The left column can narrow to 320 pixels, with wrapping controls and a separate row for draft recovery messages. Edit mode, snapping, Undo/Redo, and Download are in the command bar. The inspector contains the hierarchy, selected properties, visibility, session details, and undoable resets. Inspector sections use tabs that wrap onto multiple rows as the column narrows. The **Hierarchy** tab and its contents are visible on first load. Click another tab to switch sections, and use **Collapse inspector sections** to hide the contents. Left/Right and Home/End navigate the tabs. **Selection details** groups the selected bone or slot properties; canvas selections reveal those fields, while hierarchy navigation and skeleton commands stay in the **Hierarchy** tab. Inactive panels retain their form drafts and edits. Click the selected bone again in **Hierarchy** to deselect it. **File tools** opens validation, copy/log, reload, and local JSON import in a modal dialog; **Help** contains the shortcut table. At widths up to 900px, use **Inspector** to open the panel from the left; selecting a joint in the canvas also reveals it. Close or Escape returns focus to the Inspector button. **Reset layout** restores automatic portrait preview width, closes the drawer, and resets its scroll position without changing authored data.

The sketch remains available in both character editors with its authored animations, attachments and skins.

The sample's left shoulder and hip are on screen right, and its right shoulder and hip are on screen left, matching Animation Editor. Left limbs draw behind the body; right limbs draw in front. The left arm's visual slots use explicit global depths to keep the entire arm behind the legs as well as the torso while retaining torso parenting.

Choose **Joint Editing** to drag a joint and change its local position; descendants follow their parent transforms. Choose **Artwork Offset Editing** to move artwork relative to its bone or attachment mount. **Sprite Origin Editing** changes only the texture-local origin; the joint and offset stay fixed. **Slot Transform Editing** moves slot markers in the parent bone frame. Selecting a slot in another mode never substitutes a slot transform edit. See [visual artwork alignment](visual-artwork-alignment.md) for pivot coordinates, replacement dimensions and the forearm workflow. The inspector edits local x/y, rotation in radians, scale, logical length, sprite offset and normalized origin. It also shows degrees for reference. With a hierarchy entry focused, Up/Down select the previous/next entry, Home/End select the first/last entry, Left selects its parent, and Right selects its first child. These commands change selection without editing the rig; the hierarchy keeps one Tab stop. Outside the hierarchy and typing controls, arrow keys nudge joints, artwork offsets or slots according to the current mode by one local unit; Shift uses ten. Origin precision uses the numeric pixel and normalized fields. Comma and period rotate by 0.01 radians; Shift uses 0.1. Inputs and drags update the preview immediately. When a parent has an explicit logical length, child x/y edits set the joint's direction while that length controls its distance in both the preview and the exported runtime rig. A zero child offset uses the parent's positive y axis. Logical length changes reposition direct child joints along their current directions and do not scale images.

Bone depth edits change preview draw order; enter a lower value to move a piece back or a higher value to move it forward. Slot depth is a global numeric draw depth. **Dim unselected artwork** helps expose overlapping parts. **IK Preview** pins the current chain endpoints and runs the existing solver as the rig changes; its temporary pose does not enter the working rig. Visibility controls show artwork, bones, names, lengths, slots, origins, and IK chains. Left-button drag on the canvas background moves the whole character preview, including its pinned IK targets, without changing rig values or undo history. A background click clears the selection; a background drag keeps it. Mouse wheel zoom and middle mouse pan affect only the camera.

In **Artwork Offset Editing** mode, click and drag artwork directly to select and move it. Selecting a bone also lets you drag artwork in its attached slots; the corresponding slot becomes selected so its artwork offsets appear in the inspector. Selected artwork takes priority over overlapping bone lines and other artwork. Without a selection, overlapping artwork is picked in draw order. Square markers select slots; changing their transforms requires **Slot Transform Editing**.

Production workflow:

1. Start the rig editor and load the sample character. Select bones or slots in the hierarchy or canvas.
2. Position joints, then use Artwork Offset Editing or inspector fields to adjust artwork offsets and origins. Set logical bone lengths, slot transforms, and render depth as needed.
3. Preview IK. Use Grid (Off, 1, 2, 5, 10) for drag and nudge translation, and Rotation Snap (Off, 1°, 5°, 15°) for keyboard rotation. When Grid is on, the canvas shows lines aligned with the selected joint, slot, or artwork's local edit coordinates. At low zoom it shows a readable subset of those snap lines. Numeric fields retain exact values. Clear a numeric field and leave it to remove its authored override; omitted length and slot depth display Auto. Removing a length override keeps the current child offsets. Snapping never changes untouched values.
4. Undo with Ctrl/Cmd+Z and redo with Ctrl/Cmd+Shift+Z. A canvas drag or one numeric field focus session makes one history entry. A new edit after undo clears redo. **Reset Selected** restores the selected bone or slot and its active artwork attachment to session-start values; **Reset Rig** restores the whole session-start rig. Both resets are undoable.
5. Open **File tools** and click **Validate**. Export uses the complete versioned rig validator and blocks errors, showing their paths and messages. The session panel reports character, file, mode, selection, snapping, modified state, and validation state.
6. Click **Copy rig JSON**, **Download rig.json**, or **Log rig JSON**. Each generates readable, stable, version 1 JSON with canonical local transforms. Edited joint/slot offsets and angles use up to six decimal places, preserving small nonzero values that would otherwise round to zero. Artwork offsets and normalized origins retain full precision, so pixel pivots reload identically. Scales, lengths, depths, numeric frame IDs, and untouched numbers retain their full precision so export cannot collapse a transform or change draw order through rounding. Export marks the current working copy as the saved baseline, so Modified becomes No. Further edits become dirty; undoing back to the exported state becomes clean.
7. In **File tools**, click **Reload exported rig** to rebuild the puppet preview from the last export and verify its appearance. **Reload original rig** restores the shipped rig within the shared workspace. **Load rig JSON** accepts a local JSON file for the same character and validates it before updating the preview. The imported rig must retain the character hierarchy, bone artwork identities, IK definitions and default skin, and use textures already loaded for that character. Imports must also fit the 10 MiB limit after formatting for export; compact files that would exceed it are rejected while the current session and history remain intact.

The exported file keeps the rig name and IDs. Compatible imports also retain a changed or omitted rig name through Undo/Redo, browser recovery, and character ZIP exports. Skin files from `character.json` stay separate, and embedded skins retain their authored definitions on export. Preview merges both sources with standalone skins taking precedence, matching runtime behavior. Copy needs a browser with clipboard access; Download and Log are alternatives. Compatible reloads reuse the rig owner, retain animation sessions and applied images, and record the rig replacement in rig history. Rig Editor imports establish a JSON checkpoint; imported corrections in Rig Tweak remain authored rig changes until exported. Explicit reloads and imports skip draft recovery and remove only the replaced session’s discarded draft after the replacement succeeds; other sessions’ drafts remain stored. Leaving the editor, refreshing, or closing its tab asks for confirmation while changes are unsaved.

Unsaved authored edits also create a browser draft after a short pause and flush when leaving or hiding the page. On the next visit to the same character and rig file, the editor offers to restore a draft when its original source still matches. Restored edits remain unsaved and can be undone in one step. Declining recovery keeps the draft available for another visit or tab. **Clear retained drafts** (also available in Rig Tweak) permanently removes all remaining drafts for the current document in one click, including declined and incompatible drafts, without another confirmation. Download them first if you want a backup. Clearing leaves current edits, Undo/Redo and drafts for other documents intact; newer revisions written by another tab after recovery are preserved. Exporting, resetting, or undoing back to the saved baseline removes the current session’s draft. Drafts are local to this browser and deployment path, with independent drafts for concurrent editing sessions. When several drafts exist, recovery offers compatible drafts individually with their saved times, newest first. Drafts without valid timestamps follow in their existing order. Saving one session preserves the others. They exclude selection, camera and preview settings, and do not replace JSON exports. Malformed draft envelopes are discarded. Drafts with changed source files or incompatible rig topology are retained without being applied. **Download retained drafts** saves an archive containing each original draft envelope, its source and saved time, and its authored data (including remembered joint directions). Extract the rig from a draft's `data.rig` field for manual recovery; downloading this archive leaves browser drafts and the current saved baseline intact. If browser storage is disabled or full, the recovery status advises downloading JSON while normal editing remains available.

Undo history retains the most recent 100 operations by default, dropping the oldest entries as the limit is reached. Entries share unchanged frozen rig data; undo/redo and dirty checks do not serialize or parse the rig. Embedded editors can configure this with `new RigEditorState(rig, rigFile, { historyLimit: 250 })`; pass that state to `RigEditor`. The limit must be a nonnegative safe integer; zero disables undo/redo. Grouped drags and field edits count as one operation. Saved baselines and full-rig reset remain available after older history is dropped.

Field values are checked immediately while editing. Full rig validation runs when a drag or numeric field session finishes; the panel shows Pending during edits. Validate and export always check the current rig, including unfinished edits.

Releasing a drag outside the canvas commits one undo entry. Escape, switching windows or tabs, leaving the page, changing edit modes or disabling the editor cancels the gesture and preserves redo history. Artwork gestures preview only in Phaser until release; cancellation restores their authored appearance. Joint/slot cancellation restores the grouped working data. Camera panning stops without changing rig history. Returning to the editor allows a fresh drag immediately.

For embedded editors, `workingCopy`, `getBone()`, `getSlot()`, and `getAttachment()` return frozen readonly data. Use the state's `editBoneFields()`, `editSlotFields()`, and `editSpriteFields()` methods to preserve validation, dirty tracking, and undo history. Retained views keep their previous values after edits; request a fresh view to read the current data, or use `structuredClone(state.workingCopy)` for an independent mutable copy.

Both editor entry routes use `AnimationEditorScene`, which accepts a third options argument with `characterUrl` and optional `ikChains`. URLs resolve relative to the editor document. Preview chains default to an empty list, so other rigs can load without the demo's bone names; configured chains must be valid direct two-bone chains. The shipped editor passes the selected character's preview chains explicitly. Scene options are copied when constructed. `createRigWorkspaceController` binds the rig view to this shared scene; session controls depend only on the `RigSessionHost` interface.

The DOM panel controllers expose `dispose()` for hosts that unmount or replace editor panels. Dispose the inspector, controls, hierarchy, and session controllers before destroying the game. Disposal removes their listeners, closes an inspector edit, and prevents pending imports or clipboard results from updating detached panels. A new set of controllers can then mount on the same host elements. The React view lifetime performs this cleanup when unmounting, including during hot module replacement.

## Shared character workspace

Rig Editor and Animation Editor tabs now retain one live rig, skin catalog, applied artwork and animation document owner. Rig Tweak uses the same rig history at a paused animation pose. Editor tabs retain committed edits; character changes and leaving/reloading the workspace use the browser's unsaved-change prompt where supported. Compatible rig JSON imports retain all clips and replacement images; changing hierarchy, bone artwork identities or IK definitions requires opening another character. Downloads establish document or package checkpoints and do not overwrite served files. See the [artist workflow](artist-workflow.md) for the complete sequence.

## IK constraint authoring APIs

The [IK constraint foundation](ik-constraint-authoring.md) supplies typed model/controller commands with live animation/host dependency checks, Undo/Redo and rig JSON round trips. The [visual IK panel](rig-ik-editor.md) creates and configures constraints and provides draggable targets in Rig Editor and Animation Editor's Rig Tweak mode. Authored default targets remain puppet-local; IK Preview uses these targets when present and pins the current endpoint for older targetless constraints. Follow the [artist tutorials](artist-workflow.md#creating-ik-on-a-new-character) to create and animate a new chain.
