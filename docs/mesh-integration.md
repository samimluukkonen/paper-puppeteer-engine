# Mesh deformation across editors — v1.4.5

[All guides](../README.md#guides)

A mesh uses one authored geometry/UV/weight/bind representation and one CPU skinning evaluator. Shape corrections apply to immutable attachment-local vertices before final FK/IK skinning. Puppet placement, Actor travel, facing, scale and the camera apply afterward. See [mesh attachments](mesh-attachments.md) and [deformation animation](mesh-deformation-animation.md) for the data format and artist controls.

## Artist walkthrough

In Project Workspace, open **Feature Guide → Project Workspace → Mesh Characters Across Editors**. This nine-step Explain tour follows the same character through rigging, weights, safe artwork replacement, animation, onion-skin review, scene Actors, root travel, validation and portable saving. Only an open project is required; empty projects can explore the workflow. The tour highlights the real project controls without opening editors, creating assets, playing, validating, exporting or changing history.

For individual authoring steps, use **Editing Mesh Geometry** and **Painting Bone Weights** in Rig Editor, and **Animating Mesh Deformation** and **Onion Skinning** in Animation Editor. Their guidance includes live track protection, same-dimension mesh replacement and ghost-pose limits.

## Architecture audit

| Pipeline owner                     | Integration and compatibility                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rig Editor                         | Geometry creation, weights, skin assignment and rest validation use the existing rig/history owner. Live animation dependencies now reject edits, imports, recovery and Undo/Redo that would newly invalidate attachment or vertex references. Subdivision and surviving stable IDs remain compatible. Existing incompatible drafts can be repaired without deleting their tracks. Rest changes still require deliberate mesh recreation/rebinding. |
| Animation Editor                   | AnimationPlayer supplies bones, IK channels and shape corrections; PuppetRenderer uses final bone matrices with `createMeshSkinBinding` / `deformMesh`. Variations retime shape keys. Bone mirroring preserves shape tracks and explicitly excludes mesh retargeting; facing reflects the complete rendered character. Graph Editor supports bones, IK and root channels; deformation interpolation stays in the deformation inspector.             |
| Onion skins                        | Each ghost skins its own sampled FK pose and correction shape. Ghosts precede procedural/authored IK solving and use the current preview placement rather than sampled root travel. The Onion settings panel explains this limitation. Bake IK into bone keys to inspect solved silhouettes. Invalid topology hides ghosts.                                                                                                                         |
| Environment Preview                | Exists as independent `SceneImageLayer` artwork and a borrowed world camera around the Animation Editor's existing Puppet. It creates no second character or deformation evaluator. Background transforms, parallax and camera configuration do not alter mesh bind data.                                                                                                                                                                           |
| Scene Editor                       | Placement uses `SceneActorPreview` → Actor → Puppet; playback/scrubbing uses SceneRunner with the same runtime. Every Actor owns its geometry and animation state. Camera pan/zoom, parallax and cut/fade overlays operate outside skinning. Scene format 2 has position/facing/skin fields; standalone hosts can additionally scale Puppet containers. This milestone does not add scene scale fields.                                             |
| Actor choreography / scene runtime | Movement and root-motion ownership retain their existing conflict rules. Reconstruction seeks evaluate shape tracks through ordinary animation sampling; root travel and facing apply once outside the character skeleton.                                                                                                                                                                                                                          |
| CharacterLoader / packages         | The shared parser validates meshes, binds and correction references. Character, scene and project packages preserve authored geometry, UVs, weights, bind snapshots, texture references and animation tracks. Runtime namespacing changes texture keys without rewriting bind data. Binary headers are checked against authored mesh image dimensions.                                                                                              |
| Project Workspace                  | Dependency inspection now links mesh attachments to bind bones, bind slots and weight influences, and animations to deformation attachments. It also checks retained image dimensions against each mesh. Existing semantic validation covers missing bones, weights, topology and correction references. Missing image binaries remain warnings in drafts and block production exports.                                                             |

## Skins and replacement artwork

| Change                                     | Supported behavior                                                                                                                                                                                                                                                                    |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rigid sprite ↔ mesh in a skin slot         | Supported. Switching destroys only the replaced geometry/image and retains slot order, alpha, visibility and transforms.                                                                                                                                                              |
| Mesh ↔ another mesh                        | Supported with independently valid bind/weight/texture data. Correction tracks target attachment IDs; they do not transfer to a different attachment ID.                                                                                                                              |
| Same mesh, different artwork               | Supported when image width and height match `imageSize`, and origin multipliers remain 1. Geometry, UVs, weights and contact markers stay authored. Runtime replacement validation includes meshes in inactive skins.                                                                 |
| Different dimensions, proportions or pivot | Rejected for meshes before applying a replacement. Recreate the mesh deliberately; normalized UV stretching and automatic marker migration are unavailable. The rigid-sprite alignment policies remain available for rigid-only scopes.                                               |
| Live runtime catalog edits                 | Validate every registered deformation track before installation. Edited weights immediately refresh layer masks from the current catalog. Adding an animation after a catalog update validates against that catalog. Failed proposals retain the current rendered objects and tracks. |

Slot branches share the existing global bone/slot depth ordering for rigid and transparent mesh layers. Geometry type does not establish a separate render band. Hosts can use the ordinary slot depth override to put a sleeve behind or ahead of another part; opacity and source-over blending remain Phaser's normal behavior.

## Ownership, serialization and compatibility

Meshes borrow textures from the host texture manager. Several slots or Actors using the same texture key allocate separate geometry/bind buffers while reusing the loaded image. Character texture queueing skips loaded keys; package validation deduplicates decoding by physical image path. Distinct texture keys remain distinct Phaser resources even when they alias a file. Clearing a slot, switching skins, disposing an Actor or destroying a ghost releases its geometry, without removing shared host textures.

Portable data contains stable texture references, mesh arrays and correction tracks, never sampled geometry, browser object URLs or Phaser objects. Project packages also provide the existing recovery path; rig recovery retains geometry, UVs, weights, bind data and standalone skins before animation recovery.

Rigid characters retain omitted attachment types, version-1 formats and legacy animation behavior. They allocate no mesh objects or skin bindings. Animations without deformation tracks produce ordinary skeletal poses. Mesh2D requires Phaser WebGL; Canvas is explicitly rejected before constructing mesh characters or introducing meshes through catalog updates. Rigid Canvas characters remain supported.

## Verification

`tests/meshIntegration.test.ts` exercises live dependency rejection and history, rig recovery, animation-to-scene/project/package handoff, multiple mixed Actors, root travel, facing/scale, deterministic repeated seeks, inactive-skin replacement checks, current-weight masks, Canvas rejection, sampled ghost meshes and geometry disposal. The existing mesh, IK, root-motion, environment, renderer, scene and compatibility suites retain their focused coverage.

`scripts/check-core.mjs` loads a deformable character through the built standalone `/core` entry in plain Node, round-trips rig and shape data through `/serialization`, and checks weighted skinning, output-buffer reuse, repeated seeks and disposal. `npm run test:package` repeats this against the actual packed package installed in an isolated offline consumer and checks runtime imports, declarations and bundling.

Run `npm run typecheck`, `npm run test`, `npm run build` and `npm run test:package` sequentially. Vitest uses one worker. Browser checks remain local-only; this milestone adds no browser installations or checks to CI.
