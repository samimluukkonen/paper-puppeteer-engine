# Paper Puppeteer Engine — v0.5.3.1
## Ghost Pose Sampling Foundation

You are continuing my standalone TypeScript + Phaser project, Paper Puppeteer Engine.

**Current completed version: v0.5.2.8.3**

The engine already has a production-ready Visual Rig Editor and Visual Animation Editor, including keyframe authoring, playback, IK preview, interpolation, animation events, Undo/Redo, and JSON import/export.

Do not rebuild existing systems.

Tech stack: TypeScript, Phaser, Vite, npm, strict TypeScript, ES modules. No React or unnecessary dependencies.

## Goal

Implement the nonvisual foundation for **v0.5.3 — Onion Skinning & Ghost Poses**.

Onion skinning will display translucent copies of the character at neighboring animation times, helping artists judge motion between poses.

This phase must NOT render ghosts yet.

### 1. Ghost pose sampling

Create a reusable way to sample the animation at arbitrary times without changing the active editor pose.

Conceptually:

```ts
interface GhostPoseSample {
  time: number;
  pose: Pose;
  direction: "previous" | "next";
}
```

Adapt names and structure to the existing codebase.

The data must contain enough information for the later renderer to reproduce the sampled character pose.

### 2. Reuse the existing animation evaluator

Do not implement separate keyframe interpolation.

Sampling must use the same authored animation evaluation semantics as the production runtime.

The sampler must correctly support:
- Bone-local transforms
- Hierarchical bones
- Partial animation tracks
- Shortest-path rotation interpolation
- Smooth interpolation
- Stepped interpolation
- Existing animation settings

Use the active animation working copy, not an outdated source snapshot.

### 3. Read-only sampling

Ghost sampling must never:
- Modify the animation working copy
- Modify the source animation
- Move the editor playhead
- Change `currentTime`
- Advance playback
- Dispatch animation events
- Create keyframes
- Change Undo/Redo history
- Mark animation dirty

If the existing evaluator uses mutable runtime state, introduce the smallest safe read-only evaluation adapter or isolated evaluation context.

Do not permanently apply sampled poses to the active Puppet.

### 4. Neighboring times

Implement pure helpers to calculate neighboring sampling times.

Default spacing should represent **one authored animation frame**, based on the animation's FPS when available.

For example:

```text
Animation FPS: 10
Current time: 0.5 s

Previous ghost: 0.4 s
Current pose:    0.5 s
Next ghost:     0.6 s
```

Use the project's existing FPS conventions.

For invalid or absent FPS, use an explicitly documented fallback consistent with the engine's 8–12 FPS aesthetic.

Keep animation time continuous. Do not globally quantize the editor playhead.

### 5. Boundary behavior

Sampling must handle:
- Time 0
- Animation duration
- Short animations
- Zero-duration animations
- Missing animation
- Invalid sampling settings

At animation boundaries, **omit out-of-range samples** instead of wrapping or displaying duplicate boundary poses.

Do not implement looping ghost visualization yet.

### 6. Sampling and IK

Preserve the distinction between:
- Authored animation pose
- Procedural IK-corrected pose
- Final rendered pose

For this initial version, prefer sampling authored poses before procedural IK corrections.

Do not bake IK into animation data.

Document what is sampled and prepare an extension point for future read-only IK preview if appropriate.

Do not redesign IK.

### 7. Pure implementation

Keep time calculation and pose-sampling orchestration independently testable where possible.

Avoid Phaser and DOM dependencies in pure sampling helpers.

Use existing Pose types and animation evaluator APIs.

Do not introduce another animation timeline representation.

### 8. Tests

Add automated tests covering:
- Previous/next sampling times
- FPS-based spacing
- Start/end boundaries
- Zero-duration animation
- Partial tracks
- Stepped and smooth evaluation
- Original `currentTime` unchanged
- Working/source animation unchanged
- No animation event dispatch
- No dirty-state or history changes
- Repeated sampling produces deterministic results

### 9. Scope restrictions

Do NOT implement:
- Ghost rendering
- Translucent sprite overlays
- Onion-skin toolbar
- Multiple visible ghost poses
- Color/tint controls
- Onion-skin animation export
- New animation keyframes
- IK baking
- Physics or scene choreography

### 10. Verification

Run and fix all failures:

```bash
npm run typecheck
npm run test
npm run build
```

## Definition of done

- Read-only ghost pose sampling exists
- Neighboring sample times are calculated correctly
- Existing animation evaluator is reused
- Playback and editor state are never disturbed
- Animation events do not fire during sampling
- Tests, typecheck and build pass
